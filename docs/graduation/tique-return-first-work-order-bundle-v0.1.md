# 티크: 귀환 회로 — 첫 작업 지시 통합 번들 v0.1

작성일: 2026-09-30. 최신 main의 **docs/graduation/tique-return-first-work-order-bundle-v0.1.md**에서 읽을 수 있다.
아직 신규 구현을 지시하지 않은 상태에서 사용할 첫 작업 지시이며, 기존 v0.4 이후 요구사항을 전부 포함한다.

## 사용하는 방법

1. 다른 PC에서 기존 변경을 보존한 채 최신 main을 받아 이 파일을 읽게 한다. 저장소가 없으면 clone한다.
2. 아래 “복사할 시작 프롬프트”를 입력한다. 파일 첨부로 전달해도 된다.
3. 에이전트는 본문의 통합 실행 지시와 부록 A/B/C를 모두 직접 읽고 조사→제작→구현→실행→검증을 진행한다.

세 명세와 통합 실행 지시의 원문이 이 파일에 모두 포함돼 있다. 개별 명세도 같은 폴더에서 관리한다.
부록끼리 겹치는 단위는 재사용 관계이며 신규 클립 수로 더하지 않는다.
**최신 오프닝은 게임 안의 낙하→착지 방식**이다. AI 최종 영상이나 정지한 티크로 시작하는 이전 제안은 적용하지 않는다.
버전이 다르면 최신 사용자 요청과 Git 이력을 확인하며 오래된 번들을 최신 명세보다 우선하지 않는다.

## 2. 게임 범위와 서사

섹션 1 = 공간 퍼즐 3방, 섹션 2 = 철갑 문지기 IRON MAW와 전투 후 귀환.
티크가 귀환 회로를 복구하자 집행 장치가 재가동되고, 티크는 충전 기둥을 이용해 문지기 노심을 드러내 전원을 끊은 뒤 열린 문으로 돌아간다.
문지기 본체는 퍼즐 섹션에 등장하지 않는다. 거창한 설정·새 미니게임·장시간 컷신을 추가하지 않는다.

첫 플레이 5~6분은 사용자와 함께 검증할 목표다. 자동 정답 진행 시간을 사람의 플레이 시간으로 취급하거나 HP/대기 시간을 늘려 억지로 맞추지 않는다.

## 3. 오프닝과 실제 플레이의 연결

오프닝의 최신 결정은 **AI 영상 대신 게임 안에서 티크가 떨어져 착지하는 픽셀 연출**이다. 약 14초의 인게임 연출 뒤 같은 첫 퍼즐방·같은 캐릭터 크기·같은 발 접점에서 조작권을 넘긴다. 이전 “이미 서 있는 티크로 시작”안은 대체한다.

- Title: 픽셀 제목과 Enter 시작. 티크는 아직 화면 안에 그리지 않는다. 무입력 자동 시작 없음.
- 0~1초: 이산 검정 마스크로 첫 방을 드러내고, 위쪽 운반 통로의 덜컹 소리/작은 먼지로 원인을 암시한다.
- 1~2초: 티크가 화면 위에서 아래로 떨어진다. Jump 하강 구간을 재사용하며 상승/발차기 프레임을 섞지 않는다.
- 약 2초: 첫 퍼즐 시작 칸의 실제 발 접점에 착지. 작은 먼지·그림자·소리와 짧은 착지 압축을 같은 사건에 연결한다. 낙하 피해 없음.
- 2~3초: 착지 포즈에서 기본형으로 복귀하고 먼지를 소멸한다. 긴 쓰러짐·구르기·기상 동작 없음.
- 3~6초: 기본형에서 눈만 한 번 깜빡임. “귀환처: 엘리아스 공방.”
- 6~9초: “귀환 회로: 연결 0 / 3.”과 빈 회로 홈 3개.
- 9~11초: “…돌아갈 수 있겠네.”
- 11~14초: 대사/장식만 제거하고 “방향키로 이동 · 추를 밀어 같은 소켓에 놓기”와 퍼즐 HUD. 착지한 같은 첫 칸에서 조작권 전달.

### 낙하 에셋·VFX 판정과 실제 제작

- DO-A01/02: 기존 64×64 Jump 08~09 하강 / 10~14 착지 프레임을 직접 보고 재사용 여부를 정한다. 부족하면 보정 포즈 1~3장을 먼저 검토한다. 원본 67장/시간표를 보존한다.
- DO-A03: 작은 착지 먼지 32×16·4~5장·약 180~260ms 출발안. 기존 A11/fx-foot-dust·F15와 같은 공용 계열로 제작하여 전투 착지/대시/추 마찰에도 공유한다.
- DO-A04: 접지 높이가 읽히지 않을 때 픽셀 그림자 20×6·2~3단계를 보충한다. 원본 크기에서 불필요하면 생략 사유를 적는다.
- DO-A05/06: 원인이 불명확하면 상단 운반 통로 장식 약 48×24 정지 1장과 작은 먼지 일부를 만든다. 기존 배경 재질/팔레트 사용. 새 전체 배경/장치 물리/파괴 시스템 없음.
- DO-A07: 짧은 접촉선은 선택이다. 공격 스파크·피격 빛·영구 바닥 균열을 낙하 효과로 사용하지 않는다.
- DO-A08/09/10: 마스크·기록 UI·픽셀 한글·skip 키는 기존 계획을 공유한다. 소리는 기존 land/switch 우선, 필요할 때 짧은 통로 덜컹음만 보충한다.
- 부족한 에셋은 **판단표만 쓰지 말고 실제 PNG/프레임/시간 JSON을 제작하고 게임에 연결**한다. 생성 레퍼런스만 납품하지 않는다.

낙하는 Opening의 표시용 세로 오프셋으로 구현한다. 첫 퍼즐 렌더러의 player→발 접점 변환을 공통으로 사용하고 오프셋 0에서 접지한다. 전투 hero.x/Floor 좌표를 쓰거나 퍼즐 전체에 중력을 넣지 않는다. 낙하 동안 player/boxes/goals/이동 수/밀기 수/HP는 변화하지 않는다.
AI는 필요한 단일 참고 이미지에만 사용한다. 최종 AI 영상·AI 애니메이션 시트·소프트 파티클은 만들지 않는다. 기존 티크와 동일한 네이티브 도트 편집 과정으로 제작한다.

오프닝에서 퍼즐을 자동 해결하거나 정답 경로를 보여 주지 않는다. 첫 정상 이동/밀기는 실제 퍼즐 이력에 기록하고, 첫 유효 행동 후 처음 안내를 줄인다. 구슬·전투 조작은 해당 섹션에서 설명한다. 별도 튜토리얼 방·새 인물·공방 배경·풀 보이스·새 설정은 만들지 않는다.

현재 Journey에는 Opening이 없다. 별도 상태 또는 동등한 하위 연출 상태를 설계하고 실제 시작 경로에 연결한다. O01~O12의 연출/인계 단위와 그 하위 D01~D08 낙하 구간, DO-A01~11 자산 판단을 작업표에 연결한다. O/D는 신규 캐릭터 클립 수가 아니며 D는 O03의 상세 구간이다. 기존 TC/TP/TB/GB와 H/F/P/U를 공유한다.

Title에서 시작한 Enter가 같은 눌림으로 skip되지 않게 한다. Opening 중 새 Enter는 skip이며 자연 종료와 동일한 첫 방 상태로 한 번만 전환한다. Z/X/C는 skip에 쓰지 않는다. 넘어온 방향키/버퍼/예약 효과를 정리해서 첫 칸이 자동 이동하지 않게 한다.
Esc·창 전환에서는 연출/텍스트/소리 예약도 정지하고 복귀 시 몰아서 진행하지 않는다. 처음부터는 Title로 초기화하며 보스 재도전은 오프닝을 반복하지 않는다.

마지막 퍼즐의 소켓 도착→기존 800ms 완료 표현→Enter 진행→전투실 전력 수신/기동 약 2~3초→전투 안내 대기로 연결한다.
“귀환 동력 복구.” 뒤 “폐기 집행 장치 재가동.”으로 내가 복구한 동력이 위협을 깨웠다는 인과를 보여 준다. 기동 후 새 Enter 확인 전에는 공격/피해를 시작하지 않는다. 재도전에서는 긴 기동을 생략한다.

끝에서는 기존 문 800ms 개방→문 앞 E→“식별명: 티크. 귀환처: 엘리아스 공방.”과 귀환 허가로 오프닝의 기록을 회수한다. 꺼진 문지기를 다시 움직여 재검사하는 새 컷신은 넣지 않는다.

연출은 640×360 픽셀 계약과 기존 UI/배경/눈 깜빡임/기동 에셋을 공유한다. 새 참고 이미지가 필요할 때만 동일 제작 과정으로 보충한다.
기존 playTime 포함 범위를 확인하고 연출·안내 대기·조작 시간을 별도로 기록한다. 오프닝 시간을 더해서 첫 플레이 5~6분이 달성됐다고 보고하지 않는다.

## 4. 최소 단위와 작업표

캐릭터 기획은 TC 8 + TP 22 + TB 34 + GB 39 = 103개 행동·판정 단위다.
픽셀 피드백은 H 18 + F 30 + P 12 + U 20 = 80개 표시·효과 단위다.
오프닝 O 12개는 연출/입력 인계 단위이며 기존 단위들과 연결한다. D 8개는 O03 등의 하위 상세 구간이므로 독립 신규 클립 수로 합산하지 않는다.
이를 신규 클립 195개로 만들지 않는다. 기존 클립의 부분 재생·자세 유지·반전·타일·마스크·동일 사건 공유를 우선한다.

각 ID에 현재 구현/그림, 부족한 표현, 발생 사건, 접점·기준점, 시간, 재사용/신규/생략 사유, 검증 방법을 연결한 작업표를 먼저 작성한다.
같은 프레임이나 사건을 공유하는 단위는 중복 작업으로 세지 않는다.

## 5. 티크·문지기 동작 요구사항

- 티크 대기: 기본 실루엣·머리·몸통·하트·발 위치 고정, 눈만 감기→유지→뜨기. 현재 Unity 정적 Idle에 이미 적용됐다고 가정하지 않는다.
- 퍼즐 추: 손 닿기→뒤발 지지→함께 밀기→추 정착→힘 풀기. 구슬: 접촉→짧은 추진→손 놓기→관찰→정지. 손·물체 접점과 접지 발을 맞춘다.
- 추 이동 150ms, 구슬 이동 270ms를 유지한다. 준비 모션 때문에 입력/이동이 늦어지지 않게 한다. 막힌 밀기는 성공 이동처럼 보이지 않아야 한다.
- 되돌리기/초기화는 캐릭터·물체·소켓·불빛·효과를 함께 복구한다. 소켓 접속은 실제 화면상 물체 도착 후 시작한다.
- 전투 점프는 첫 추진/상승/정점/하강/접지, 두 번째 공중 추진을 실제 물리 상태에 연결한다. 대시 160ms 이동과 440ms 그림 클립을 혼동하지 않는다.
- 공격은 사용자가 선택한 뒤쪽 팔의 짧은 주먹을 유지한다. 준비→유효 타격→명중 또는 빗나감→복귀→점프/대시 취소를 구별한다. 팔 길이를 늘리지 않는다.
- 티크 피격은 접촉 움찔→조작 복귀→보호 종료, 마지막 피해는 전원 저하→실패, 재도전은 상태 초기화로 구별한다. 긴 경직/강제 넉백을 임의로 추가하지 않는다.
- 문지기는 전력 수신→지지 다리 잠금→대기, 돌진 탐색→방향 확정→발동→진행→충돌 결과를 분리한다.
- 일반 벽 충돌과 충전 기둥 충돌을 다르게 표현한다. 기둥 충돌만 방전·장갑 개방·노심 노출로 이어진다.
- 장갑 열림→열린 자세 유지→노심 피격→열린 자세 복귀→닫힘→잠금 복구. 매 타격에 개방 모션이나 노출 타이머를 재시작하지 않는다.
- 충격파 준비/첫 방출/강화 두 번째 방출, 낙하 접지 압축/상승/지점 추적/확정/하강/바닥 접촉/강화 파형/복귀를 연결한다. 겹치는 조준과 몸동작을 순차 재생해 예고 시간을 늘리지 않는다.
- 최종 타격→전원 차단→정지 유지→배경 복구→문 개방→E 귀환을 연결한다. 종료 후 남은 파형이 티크에게 피해를 주지 않게 한다.
- 입장 안내는 Enter 확인 후 첫 공격이 시작되게 한다. 안내 자동 종료 때문에 읽기도 전에 공격받지 않게 한다.

## 6. 조작과 유지할 전투 규칙

전투: 방향키 이동, Z/Space/↑ 점프, X 공격, C 대시, E 충전·문 조작.
퍼즐: 방향키/WASD 이동, Z/Backspace 되돌리기, R 초기화, H 힌트.
섹션별 입력 분기·화면 키 안내·자동 검사 입력을 함께 맞춘다. 이전 J/Shift 표기는 변경 전 기록이다.

점프/대시 입력 성공 즉시 물리가 시작된다. 모션·효과 완료를 기다리느라 조작을 잠그지 않는다.
동시 입력 우선순위와 공격 취소를 명시하고, 취소한 공격의 유효 판정을 남기지 않는다.

티크 HP 5, 보스 HP 9, 유효 1타 피해 1, 한 공격당 한 번, 노출 5.2초·최대 3타, 충전 16초·마지막 3초 만료 예고, 피격 보호 1.1초, 보스 명중 정지 45ms를 기준으로 한다.
이동 속도·예고·반격·도움 모드 수치는 현재 모델을 유지한다. 도움 모드의 실제 시간을 게이지에 반영한다.
회복약·실드·스태미나·치명타·콤보 시스템·새 전투 페이즈를 추가하지 않는다.

## 7. 전부 픽셀로 맞출 HUD·VFX·UI

### 체력 HUD

티크는 하트 동력계 5칸, 보스는 철갑 동력계 9칸·3칸마다 구획 홈.
프레임/채움/빈 홈/피해 접수/소실 잔상/저체력/보호 표시/마지막 소실/재도전 채움/보스 강화 경계를 분리한다.
실제 HP는 피해 순간 즉시 반영한다. 150~250ms 소실 잔상 때문에 체력이 아직 남은 것처럼 보이지 않게 한다.
재도전 채움은 초기화 표현이지 전투 중 회복이 아니다.

### 타격·이동·보스 효과

- 노심 명중: 접점 흰 핵→작은 픽셀 스파크 확장→짧은 파편 소멸. 내부 core-hit와 접점 효과의 역할을 나눈다.
- 닫힌 장갑: 실제 접촉한 경우만 탁한 금속 칩. HP 감소/성공 스파크/명중 정지는 없음.
- 허공: 짧은 주먹 호만 종료. 스파크·피해 숫자 없음.
- 티크 실제 피격: 별도 접촉 파열과 보호 표시. 무적 중 접촉을 새로운 피해처럼 반복 표시하지 않는다.
- 첫 점프/착지/지상 대시 먼지, 공중 두 번째 추진, 대시 잔상, 종료/사용 가능 상태를 구별한다.
- 일반 벽 충돌, 충전 기둥 방전, 장갑 열림/닫힘, 돌진·낙하 추적/확정, 충격파 생성, 낙하 바닥 충격과 강화 신호를 보완한다.
- 퍼즐 손 접촉/추 마찰/구슬 정지/막힘/오접속/연결 해제/되돌리기/회로 복구를 필요한 만큼만 보강한다.

### 빠뜨리면 안 되는 보충 에셋

픽셀 한글 글꼴·숫자·키 글리프, 패널 타일, 버튼 기본/선택/눌림/비활성, 키 캡·행동 아이콘, 되돌리기/초기화/힌트, 회로 0~3 진행, 충전/노출 게이지, 선택 커서, 안내/실패/완료 카드.
OS 폰트/기본 GUI 버튼이 남아 화면 스타일을 깨지 않게 한다. 글꼴 원본·배포 라이선스·실제 문구의 글리프 누락을 확인한다. 이미지 생성으로 글자를 만들지 않는다.
대시 준비 표시·노출 내 타수 표시가 더 혼란스럽다면 생략 사유를 기록한다.
전체 화면 플래시·거대한 폭발·지속적인 장식 입자는 MVP에서 제외한다. 소리 없이도 성공·실패·위험을 읽을 수 있어야 한다.

## 8. 제작 과정과 기존 자산 보존

티크에서 확립한 **기준 고정→단일 참고 이미지→네이티브 픽셀 편집→프레임/시간 내보내기→상태 연결→검토** 과정을 티크·문지기·HUD·VFX에 반복한다.
먼저 process-history와 기존 제작 도구를 확인해서 이미 겪은 비율·접점·타이밍 문제를 다시 만들지 않는다.

- 티크 64×64·기준점 (32,56), 문지기 192×144·발 기준선 132px, 기존 팔레트·실루엣을 보존한다.
- 이미지 생성이 필요하면 해당 환경의 imagegen 스킬을 읽고 신규 묶음의 단일 참고 이미지만 만든다.
- 승인된 네이티브 도트의 픽셀 덩어리를 정수 이동하고 연결부를 편집한다. 프레임마다 전체 캐릭터 재생성, AI 완성 애니메이션 시트 잘라쓰기, 런타임 본체 부품 리깅으로 전환하지 않는다.
- PNG·가변 시간 JSON·Piskel·APNG·픽셀 변경 기록을 보존한다. Piskel 20FPS 편집 미리보기와 실제 가변 런타임 시간을 구분한다.
- 티크 67장·문지기 52장·장치 37클립/187 PNG 노출 프레임을 보존한다. 기존 소켓·기둥·노심·문·경고·파형·복구 배경을 새로 전부 생성하지 않는다.
- 이미 읽히는 표현이면 신규 제작을 생략한다. 코드로 도트를 편집했다면 그렇게 기록하고 Piskel UI에서 직접 그렸다고 주장하지 않는다.
- 새 레퍼런스만 만든 것을 게임 적용 완료로 보고하지 않는다.

## 9. 렌더링·사건 연결 계약

월드와 HUD 모두 640×360 논리 좌표, Point, mipmap 없음, 무압축, 정수 좌표/확대.
1280×720 2배, 1920×1080 3배. 비정수 창은 정수 viewport+letterbox, 최소 창 정책과 고DPI 실제 렌더 픽셀도 확인한다.
패널은 타일/정수 9-slice, 게이지는 정수 길이 클리핑. 부드러운 bloom/gradient/소프트 파티클/임의 회전·확대를 피한다.
기본 원본 알파는 0/255, 광원은 팔레트 단계/작은 도트 후광, 잔상은 이산 단계로 검토한다.

HP 감소·타격 그림·접점 스파크·소리·45ms 정지는 같은 명중 사건에서 한 번 발생한다.
장갑 접촉은 피해 검사 실패만으로 추정하지 말고 실제 접촉 위치를 확인한다.
접점·방향은 사건 발생 시 저장한다. 타격 뒤 움직인 대상에 스파크가 끌려가지 않게 한다.
hit-stop 동안 접촉 핵을 유지하고 해제 후 확장/소멸을 진행한다. 정지 종료용 시계까지 멈춰 무한 정지를 만들지 않는다.
pause/focus-loss에서는 세계 시간·VFX·예고·충전/노출을 함께 정지한다. retry/undo/reset/장면 전환에서는 오래된 효과를 정리한다.
먼지가 위험 표시를 덮거나 스파크가 주먹·노심을 가리지 않게 한다. 주먹 호가 실제 사거리보다 길거나 낙하 먼지가 피해 범위를 과장하면 수정한다.

## 10. 단계별 제작·실행 워크플로우

1. 현재 상태 재현: 기존 검사·빌드·플레이로 기준 화면과 문제를 기록하고 ID 작업표 작성.
2. P0 샘플: 네이티브 HUD/한글/기본 UI 1화면, 노심 성공/장갑/허공/티크 피해, 조준 확정·약점·게이지의 최소 세트. 첫 방의 낙하→실제 시작 칸 착지→기록→조작권 인계도 기존 그림으로 먼저 연결.
3. 핵심 동작: 추/구슬 접촉, 티크 피격, 문지기 충돌/장갑 유지, 점프·대시·공격 전환. P0 효과와 함께 실제 사건에 연결.
4. 연결 보완: 오프닝 낙하/착지·먼지/눈 깜빡임/기록/skip, 첫 퍼즐 안내, 기둥/문 접촉, 복구→기동/차단, 강화 예고, Enter 입장, 키 배치, 귀환 기록 회수.
5. P1 손맛: 먼지·잔상·충전 브리지·낙하 충격·퍼즐 접촉. 기존 장치 아트와 스타일 비교.
6. 검증/빌드: 현 PC에서 실행 가능한 결과를 만들고 사용자가 직접 플레이할 시작 화면으로 연다.
7. P2 장식은 필수 항목 검증 후. 시각·재미의 최종 승인은 사용자와 진행한다.

통상적인 구현 선택마다 승인을 기다리지 말고 정해진 범위에서 진행한다.
기준 캐릭터/세계관 변경, 새로운 규칙, 유료 구매·외부 배포·권한 확대가 필요하면 먼저 요청한다.
환경/라이선스/필수 자료가 막히면 원인과 필요한 사용자 조치를 구체적으로 보고하고 가능한 안전한 작업을 진행한다.

## 11. 검증과 완료 보고

기존 검사에 실제 전환/접촉/사건 중복 검사를 추가한다. 검사를 통과시키기 위해 원본 보존 조건을 완화하지 않는다.
Title→Opening→퍼즐 3방→보스→엔딩, 실제 키 입력, 되돌리기·초기화, 피격·재도전, 점프/대시/공격 취소, 보호·무적, 충전 만료·노심 종료, 강화 경계, 최종 타격·문 800ms 개방·귀환을 확인한다.
HP 5→0/9→0, 한 공격 1회 피해/스파크/소리, 허공·장갑·무적에서 거짓 피해 없음, pause/focus-loss/hit-stop 상태 정리를 확인한다.
오프닝 자연 종료와 낙하 전/낙하 중/발 접촉/먼지 소멸/기록 표시 중 skip의 첫 방 상태 일치, Enter/방향키 유지 시 입력 누출 없음, 연출 중 pause/focus-loss, 처음부터 초기화, 재도전 오프닝 생략을 확인한다. 마지막 소켓→기동→안내 확인→첫 공격은 일반 입력 경로로 검증한다.
낙하 발 접점 일치, Title에 티크가 미리 보이지 않음, 티크/먼지/착지음/접촉 사건 1회, 낙하 피해·퍼즐 이동 기록 없음, 기존 하강/착지 재사용의 접지·비율을 확인한다.
원본 크기·느린 재생·720p·1080p·비정수 창·고DPI에서 접점/발 접지/픽셀 격자/한글/위험 판독을 확인한다.

# 부록 A — 티크·문지기 두 섹션 최소 동작 명세

# 티크: 귀환 회로 — 두 섹션 최소 동작 기획 v0.1

작성일: 2026-09-30. 상태: 기획 제안. 게임 코드·프레임·입력·전투 수치는 변경하지 않는다.

## 1. 범위와 읽는 방법

현재 실행한 Unity v0.4를 기준으로 **섹션 1 = 귀환 동력실의 공간 퍼즐 3방**, **섹션 2 = 폐기 집행실의 철갑 문지기 전투와 귀환**으로 정의한다. 문지기 체력에 따른 강화 구간은 섹션 2 내부의 전투 단계다.

최소 동작은 플레이어가 의미를 구별할 수 있는 가장 작은 행동 구간이다. 준비 자세, 접촉, 이동, 판정, 복귀를 따로 정의한다. **동작 ID 하나가 신규 애니메이션 파일 하나를 뜻하지 않는다.** 같은 그림을 유지하면서 판정만 달라지는 구간도 있으며 기존 프레임의 부분 재생·고정·좌우 반전을 우선한다. 눈·손목·발가락처럼 실제 화면에서 식별되지 않는 모든 관절을 별도 작업으로 늘리지는 않는다.

표의 시간은 기존 수치를 유지하는 출발점과 새 동작의 제안을 구분한다. 새 표현은 기존 동작 시간 안에 배치하는 것을 우선한다. 밀기나 점프 전에 새 준비 시간을 덧붙여 조작을 늦추지 않는다.

### 현재 확인한 기준

| 항목 | 현재 v0.4의 기준 |
|---|---|
| 티크 자산 | 64×64, 접지 기준점 (32,56), 원본 프레임 67장 |
| 원본 클립 | Idle 1장·1,000ms / Walk 14장·760ms / Attack 12장·460ms / Dash 12장·440ms / Jump 15장·800ms / DoubleJump 13장·710ms |
| 퍼즐 | 빈 칸 이동·추 밀기 150ms, 구슬 밀기 270ms. 물체가 도착한 후 소켓 연결 표현 |
| 전투 이동 | 이동 88px/s, 대시 325px/s·160ms, 대시 재사용 대기 450ms |
| 전투 공격 | 전체 460ms. 0–120ms 준비 / 120–220ms 유효 타격 / 220–460ms 복귀. 한 공격에서 같은 적에 한 번만 피해 |
| 점프 | 첫 점프 초기 속도 245px/s, 두 번째 220px/s, 중력 800px/s², 착지 표현 120ms |
| 보호 | 대시 중 무적, 피격 후 1,100ms 보호, 보스 명중 시 45ms 정지 |
| 문지기 | 192×144, 발 기준선 132px. Idle 1·Attack 12·Charge 12·Slam 15·Stagger 12 = 52장 |
| 전투 규칙 | 충전 유지 16초, 마지막 3초 만료 예고. 노심 노출 5.2초, 한 노출 최대 3타, 총 9타 |
| 보스 예고 | 충격파 1.05초, 돌진·낙하 1.25초. 돌진 방향 추적 첫 350ms / 낙하 지점 추적 첫 450ms |

클립 총 시간과 물리 동작 시간은 다르다. 대시 그림 440ms를 이동 160ms로 늘려 해석하지 않는다. 점프 그림 800ms도 실제 비행 시간과 같다고 가정하지 않는다. 구간별 그림을 실제 물리 상태에 연결한다.

현재 Unity의 티크 대기는 정적 1장이다. 이전에 선택한 **기본형 유지 + 눈만 깜빡임**을 이번 기획의 목표로 두되, 이미 Unity에 적용됐다고 표현하지 않는다.

## 2. 티크 공통 동작

| ID | 최소 단위 | 자세·화면 의미 | 진입 → 종료 | 시간·판정 |
|---|---|---|---|---|
| TC01 | 기본 대기 | 머리·몸통·하트·접지 위치 고정. 다음 입력을 기다림 | 동작 복귀 → 입력/깜빡임 | 계속 유지. 몸통 흔들기 없음 |
| TC02 | 눈 감기 | 눈의 열린 면적만 줄임 | 대기 중 깜빡임 시작 → 감김 | 제안 80ms. 기본형 픽셀 보존 |
| TC03 | 눈 감김 유지 | 눈이 잠시 닫힘 | 감기 끝 → 뜨기 | 제안 100ms. 몸체 이동 없음 |
| TC04 | 눈 뜨기 | 기존 열린 눈으로 복귀 | 감김 끝 → 기본 대기 | 제안 80ms. 공격 예고 대응 중에는 시작 억제 |
| TC05 | 방향 전환 | 입력 방향으로 시선·몸 방향이 바뀜 | 방향 입력 변경 → 이동/대기 | 좌우는 즉시 반전. 회전 연출 때문에 입력 지연 없음 |
| TC06 | 이동 접지 A | 한 발이 바닥을 지지하고 몸 중심을 전달 | 보행 시작/순환 → 통과 자세 | 기존 Walk 시간 배열·기준점 사용 |

| TC08 | 이동 정지 | 다음 칸/목표 지점에서 체중을 회수 | 이동 끝 → 기본 대기 | 물리 정지 즉시. 마지막 접지 자세 재사용 |

상하 이동은 퍼즐의 논리 방향이다. 캐릭터 전체를 90도로 돌리지 않는다. 기존 3/4 실루엣과 좌우 형태를 유지하고, 상하 이동의 발 디딤·손 접촉 변형이 필요한지 실제 크기에서 판독해 결정한다.

## 5. 문지기 — 섹션 1에서의 역할

현재 섹션 1에는 문지기 본체가 등장하지 않는다. 퍼즐 진행 중 문지기에게 순찰·공격·추적 동작을 추가하지 않는다. 세 회로의 복구 불빛과 마지막 완료 문구가 문지기 재가동의 원인을 설명한다.

본체 동작은 섹션 2 입장 시점의 GB01–04로 시작한다. 완성한 퍼즐이 다음 위협을 깨웠다는 인과를 보여 주되, 입장 안내를 기다리는 동안 첫 공격이 시작되지 않도록 설계한다. 현재 안내는 Enter 또는 6초 후 전투가 시작되는 방식이므로, **기획 제안은 첫 안내를 읽고 Enter를 누른 뒤 공격 시작**이다. 입장 모션을 보여 주는 시간과 조작 설명을 읽을 시간은 따로 다룬다.

## 9. 중단·동시 입력·경계 상황의 기획

아래는 앞으로 적용할 규칙 제안이며 현재 코드를 모두 보장한다고 표현하지 않는다.

1. **퍼즐 입력 단위:** 성공한 한 칸 이동/한 번 밀기만 이력에 남긴다. 실패 입력은 움직임·밀기 수를 증가시키지 않는다. 모션 중 다음 이동은 짧게 버퍼하거나 무시하는 정책 하나로 통일하고, 모션을 중간에서 끊어 물체 접점을 바꾸지 않는다.
2. **퍼즐 복구:** 되돌리기·방 초기화는 티크, 물체, 연결 소켓, 전력 표시를 같은 복구 상태에서 다시 계산한다. 별도의 회로 성공 애니메이션이 혼자 남지 않는다.
3. **격자 네 방향:** 이동·접촉 방향별 접점을 정의한다. 좌우는 반전 공유, 위아래는 기존 실루엣을 유지한 손/발 위치의 최소 변형 후보를 검토한다. 4방향 전 동작을 먼저 새로 만들지 않는다.
4. **같은 틱의 전투 입력:** 대시·점프·공격·상호작용의 우선순위를 명시한다. 제안은 대시 → 점프 → 공격 → 상호작용이고 좌우 이동은 가능한 동작에서 병행한다. 취소한 공격의 피해 판정은 같은 틱에 남지 않는다.
5. **그림보다 조작 우선:** 점프·대시가 가능한 상태라면 입력 소비 순간 물리가 시작된다. 준비·착지·충전 손동작을 다 볼 때까지 기다리게 하지 않는다. 보스는 충분한 예고가 끝난 뒤 발동한다.
6. **접지:** 걸음·밀기·공격 중 기준 발은 바닥에 둔다. 대시 끝 공중에서는 낙하, 지상에서는 접지로 복귀한다. 공중에서 지상 마무리 자세를 선택하지 않는다.
7. **피격:** 피해 확정 → TB29 반응 → 보호 중 조작 복귀 순서. 몸의 반응, 건강 수치, 소리의 사건을 분리 저장하지 않는다. 강제 이동/경직 시간 추가는 별도 재미 조정이다.
8. **장갑 개폐:** 열리는 시작과 취약 시작, 닫히는 시작과 취약 종료를 하나의 규칙으로 표시한다. 문서의 기획 기준은 현재 모델처럼 기둥 충돌 시 취약 시작, 닫기 시작 시 취약 종료다. 철판이 열리기 전에도 맞을 수 있는 구간의 노심은 즉시 보여야 한다.
9. **노심 피격과 본체 자세:** 피격 효과는 열린 자세 위에서 재생한다. 타격을 받을 때마다 장갑이 닫히거나 노심 위치가 바뀌면 안 된다.
10. **마지막 피해:** 티크/보스의 최종 피해 상태가 결정되면 다음 행동의 입력·공격 이벤트를 정리한다. 보스 종료 뒤 이미 존재하던 파형이 티크를 죽이는 상황은 허용하지 않는다.
11. **정지·창 전환:** 게임 시간·모션 시간·예고·노출·충전 만료를 함께 정지한다. 복귀 후 새 입력을 기다리고 이전 키가 눌린 상태로 계속 공격하지 않는다.
12. **키 배치:** 현재 실행본의 키를 문서 기준으로 사용했다. 이전 사용자가 지정한 전투 Z 점프/X 공격/C 대시로 통일하는 제안은 별도 변경 항목이다. 퍼즐 Z 되돌리기는 섹션이 달라 공존할 수 있다. 이 문서를 쓰면서 키를 바꾸지 않는다.

## 10. 제작·검토 묶음

캐릭터 동작 103개는 **티크 공통 8 + 퍼즐 22 + 전투 34 + 문지기 39**개의 행동/판정 구간이다. 이는 103개 신규 클립이나 PNG 수가 아니다.

### 기존 자산으로 먼저 검토할 묶음

- 티크 기본형·Walk·Jump·DoubleJump·Attack·Dash의 구간 재사용. 주먹은 선택한 뒤쪽 팔 공격을 유지한다.
- 문지기 Idle·Charge·Attack·Slam·Stagger의 부분 재생과 준비/정점/노출 자세 유지.
- 현재 추·구슬·소켓·기둥·노심·전원 차단·문·경고·복구 배경의 상태 그림.
- 대기 눈 깜빡임은 앞서 선택한 기본형의 눈 수정안을 참고한다. 현재 Unity의 정적 Idle과 구분해서 편입을 기획한다.

### 새 키 포즈가 우선 필요한 묶음

| 우선순위 | 묶음 | 최소 표현 목표 | 왜 필요한가 |
|---|---|---|---|
| 1 | 티크 추 밀기 | 손 접촉 / 지지 / 이동 / 힘 풀기 | 걷기만으로 설명하기 어려운 무게·접점을 전달 |

| 1 | 티크 피격 | 접촉 움찔 / 조작 복귀 / 최종 실패 | 피해가 난 순간과 보호 중 행동 가능을 구별 |
| 1 | 문지기 충돌 결과 | 일반 벽 제동 / 기둥 충돌 / 열린 장갑 유지 | 기둥을 이용해야 반격할 수 있음을 전달 |
| 2 | 티크 기둥·문 접촉 | 손 접촉 / 손 회수 | E 상호작용의 원인과 결과를 연결 |

| 2 | 강화 예고 | 두 번째 충격파 / 착지 파형 신호 | 기존 동작의 강화 내용을 피해 전에 알려 줌 |

현재 기존 프레임에서 원하는 포즈가 읽힌다면 그 묶음의 새 프레임 제작을 생략한다. 접촉·접지·피격의 부족이 확인된 부분부터 만든다. 각 묶음의 최종 프레임 수는 키 포즈 검토 후 결정한다.

### 동일한 제작 과정을 적용하는 계약

1. 동작 ID와 실제 사건, 기준점·접촉면·실루엣을 먼저 확정한다.
2. 필요한 동작별 단일 참고 이미지만 생성한다. 기준 캐릭터 비율·색·재질을 고정한다.
3. 승인한 기준 도트에서 픽셀 덩어리의 정수 이동과 픽셀 편집으로 키 포즈·중간 프레임을 만든다.
4. 완성된 투명 PNG 프레임과 가변 시간 JSON으로 재생한다. 몸체를 런타임 부품 리깅으로 바꾸거나 매 프레임 전체 캐릭터를 새로 생성하지 않는다.
5. 편집 가능한 Piskel, PNG 시트, APNG, 기준 도트 대비 변경 좌표를 보존한다. Piskel의 균등 편집 재생을 게임 타이밍 증거로 쓰지 않는다.
6. 실제 크기·느린 재생·접촉 비교·실제 입력 전환으로 검토한다. 이미지 품질과 조작 규칙의 승인 항목을 각각 기록한다.

티크와 문지기의 캔버스·몸 구조는 다르지만 기준 고정 → 도트 편집 → 프레임/시간 내보내기 → 게임 상태 연결 → 검토 과정은 같다. 준비 자세나 노출 자세의 유지 시간은 게임 규칙에서 정하고, 프레임을 비균등 확대해서 시간을 맞추지 않는다.

## 2. 시각 언어와 변경하지 않을 규칙

### 시각 언어

- 티크: 하트 모양의 작은 동력계 + **5칸**. 시안은 정상 동력, 흰 핵은 순간 접촉, 어두운 빈 칸은 소실.
- 문지기: 철제 프레임 + **9칸, 3칸마다 홈**. 붉은/주황 노심 동력과 기계 재질을 사용한다.
- 일반 벽/장갑 접촉: 짧고 탁한 황동·회색 파편. **노심 열림의 시안 방전과 다르게** 만든다.
- 유효 노심 타격: 작은 흰 중심 → 주황/시안 외곽 → 분리되는 몇 개의 픽셀. 성공한 접점을 강조한다.
- 위험 예고: 위험 범위와 방향은 기존 경고를 우선한다. 추적 중은 끊긴 선, 확정은 잠금 모서리/고정 화살표로 구별한다.
- 퍼즐: 기존 추/노란 소켓은 사각 계열, 구슬/시안 소켓은 원형 계열을 유지한다. 색 없이도 종류·성공·실패를 구별한다.
- 장식은 회로·볼트·철판 홈으로 제한한다. 다른 작품의 체력바/이펙트를 그대로 복사하지 않는다.

### 게임 규칙은 그대로

티크 HP 5, 보스 HP 9, 1타 피해 1, 노출 최대 3타/5.2초, 충전 16초, 피격 보호 1.1초, 대시 이동 160ms, 보스 명중 정지 45ms를 기준으로 한다.
도움 모드의 다른 시간은 실제 모델 값을 표시한다. 게이지에 기본 시간 상수를 따로 복사하지 않는다.

회복약·실드·스태미나·치명타·콤보 점수·드롭 아이템은 현재 규칙에 없으므로 추가하지 않는다.
칸이 다시 채워지는 연출은 **재도전 시 초기화**이지 전투 중 체력 회복이 아니다.
대시 준비 표시는 실제 사용 가능 조건을 설명하는 보조 표시이며 새 자원 시스템이 아니다.

### 글꼴은 빠뜨리면 안 되는 에셋

현재 OS 동적 폰트는 한글이 보인다는 장점은 있지만 픽셀 글꼴이 아니고, PC마다 같은 모양/폭도 보장되지 않는다.
특정 Mac 설치 글꼴을 파일째 넣어도 된다고 가정하지 않는다. **사용·수정·배포 가능한 라이선스의 원본을 확인한 뒤** 픽셀 글리프/비트맵 아틀라스를 사용한다.

최소 MVP는 실제 안내·버튼·기록 문자열에 등장하는 글자를 모으고, 네이티브 12–16px 크기에서 판독 가능한지 검토한다.
문자열이 늘어날 때 필요한 글리프를 검사하는 도구와 명확한 대체 글리프를 둔다. 임의 문장 입력 기능이 없다고 한글 전체가 이미 지원된 것으로 주장하지 않는다.
최종 UI 문구를 먼저 짧게 확정하면 글리프·레이아웃 비용이 줄어든다. 이미지 생성으로 한글 글꼴이나 키 글자를 만들지 않는다.

충전 게이지와 노출 게이지는 기존 위치를 우선한다. 같은 정보의 HUD/월드 중복은 최소화한다.
노출 타수 3칸은 총 보스 HP 9칸과 모양/위치를 구별하고 “이번 개방에서 남은 타수”임을 보여 줘야 한다. 실제로 더 혼동되면 타수 표시를 생략한다.

### 티크와 같은 과정, VFX에 맞는 크기

1. 실제 사건과 접점, 기존 동작 ID, 기준 해상도, 팔레트를 확정한다.
2. 필요한 묶음만 단일 참고 이미지/상태 보드를 만든다. 이미지 생성은 디자인 방향 참고용이다.
3. 승인된 네이티브 픽셀 원본에서 정수 좌표 편집으로 키 프레임을 만든다. 이미지를 매 프레임 다시 생성하거나 AI 완성 애니메이션 시트를 잘라 쓰지 않는다.
4. PNG, 가변 시간 JSON, 편집 가능한 Piskel, APNG, 기준 프레임 대비 픽셀 변경 기록을 보존한다.
5. 실제 1배 크기 → 느린 재생 → 2배/3배 게임 화면 순서로 검토한다. 효과 시간은 기본 Attack 460ms를 무조건 복사하지 않는다.
6. 신규 원본 경로 제안은 art/return-v5-feedback, 게임 복사본은 Assets/Resources/ReturnV2/Feedback이다. 경로는 구현 작업표에서 확정한다.

### 렌더링 조건

- 월드와 HUD 모두 **640×360** 논리 좌표계에서 픽셀 단위로 배치한다. 1280×720은 2배, 1920×1080은 3배.
- 창이 다른 크기면 정수 배율 viewport와 남는 공간의 letterbox를 사용한다. 640×360 미만의 지원/최소 창 정책도 명시한다.
- Retina/고DPI에서 논리 창 크기와 실제 렌더 타깃 픽셀 수를 구분해서 검사한다. 정수 확대 설정만 보고 검수 통과로 처리하지 않는다.
- HUD/글꼴/커서도 Point, mipmap 없음, 무압축을 기본으로 한다. 원본 테두리는 정수 좌표, 확대 배율에만 맞춰진다.
- 패널은 픽셀 타일 반복 또는 정수 단위 9-slice. 중심/변을 임의 비율로 늘려 장식 픽셀을 찌그러뜨리지 않는다.
- 게이지는 정수 길이 클리핑/타일 개수로 채운다. 필요하다면 1×1 픽셀은 사용할 수 있지만 프레임·형태·눈금은 디자인한다.
- 효과 회전이 필요하면 직접 만든 방향 프레임/90도 회전·반전을 우선한다. 임의 각도의 연속 회전/스케일로 픽셀 격자를 흐리게 하지 않는다.
- 광원은 팔레트 단계와 작은 도트 후광/디더로 만든다. 흐린 bloom·smooth gradient·소프트 파티클은 사용하지 않는다.
- 기본 원본 알파는 0/255. 잔상/보호 효과는 이산 팔레트/마스크 단계로 검토한다. 반투명 전체 사각형이 그림을 덮지 않게 한다.
- 효과는 네이티브 위치가 매 프레임 정수화되도록 하되 물리 판정 좌표를 도트에 맞춰 바꾸지는 않는다.

### 정렬과 가림 규칙

배경/기계 → 바닥 먼지 → 바닥 위험 경고 → 캐릭터/장치 → 접점 스파크 → HUD 순서를 출발점으로 검토한다.
유효 타격은 본체보다 밝지만 작게, 조준 경고는 먼지보다 명확하게 둔다.
F28 낙하 효과는 실제 피해 범위보다 넓은 위험 면처럼 보이지 않도록 낮고 얇게 만든다.
단일 타격 효과는 노심 실루엣의 과반을 가리지 않는 것을 출발 기준으로 삼는다. 동시 스파크는 검토 상한 2개, 같은 사건의 중복은 제거한다.

전체 화면 번쩍임은 MVP에서 제외한다. “효과 감소”에서는 흔들림·잔상·장식 점멸을 줄이되 피해/조준/취약 정보는 고정 형태로 유지한다.
새 접근성 옵션의 코드 구현은 별도 작업표에서 추적하며 현재 이미 존재한다고 표현하지 않는다.

## 9. 사건 연결과 타이밍 — 에셋만 만들어 놓지 않기

| 기준 사건 | 동작 ID | 연결할 효과/HUD | 검증할 조건 |
|---|---|---|---|
| 성공한 노심 타격 | TB22–23 / GB17–18 | H13–14, F02–04, 기존 core-hit, 소리/45ms 정지 | 같은 attackSerial에 한 번. HP·접점·시간 동일 |
| 닫힌 장갑 접촉 | TB24 | F05, 금속 소리 | 실제 충돌/접촉을 따로 확인. 성공 판정/HP 감소 없음 |
| 허공 공격 | TB24 | F01→F06 | 공격 버튼을 눌렀다는 이유만으로 스파크 생성 금지 |
| 티크 실제 피해 | TB29–30 / GB11 등 | H04–07, F08–09 | invincible/dash면 피해·피격 효과 없음 |
| 기둥 충돌 | GB13–16 | F22–24, 기존 discharge·core-exposed | 실제 충전 소비 1건이 공통 기준 |
| 일반 벽 충돌 | GB12 | F21 | 노심 열림/기둥 방전 없음 |
| 실제 접지 | TB13 / GB34 | F15 또는 F28 | 같은 접지 프레임을 반복 피해/먼지로 세지 않음 |
| 조준 확정 | GB07 / GB31 | F25 / F27 | 표시 좌표와 공격 확정 좌표 일치, 뒤늦은 추적 없음 |
| 물체 도착·접속 | TP07/12/14 | P03/05/07, 기존 socket-connect | 논리 점유가 먼저 바뀌어도 시각 도착 후 접속 |
| 되돌리기·초기화 | TP17–18 | P10, U09, 상태 에셋 재계산 | 오래된 접속·먼지·완료 효과를 제거 |
| 전투 최종 타격 | GB37–39 / TB33 | H16, F11/30, 기존 문·배경 | 잔여 파형 피해 중단. 전원 복구/문 개방으로 이어짐 |

attackSerial, damageEventId, transitionSequence 같은 사건 키는 구현 설계 후보이지 현재 API가 모두 있다는 뜻이 아니다.
노심 명중은 기존 이벤트를 확장하고, 장갑 접촉은 현재 피해 검사 실패만으로 만들어 내지 않는다.
캐릭터/대상/효과의 접점 위치와 방향을 사건 발생 시 저장한다. 닿은 뒤 보스가 움직였다고 효과가 따라붙어 미끄러지지 않게 한다.

**시간 정책:**

- HP 숫자·칸의 실제 상태는 피해 확정 즉시 갱신한다. 소실 애니메이션은 뒤따르는 장식이다.
- 보스 명중 순간 45ms 동안 본체를 멈추고 F02 접촉 핵을 유지한다. 정지 해제 후 F03–04가 진행되게 하여 정지 시간에 스파크가 다 사라지지 않게 한다.
- hit-stop 종료용 시간은 정상적으로 흘러야 한다. 그 시계를 함께 멈춰 무한 정지가 생기면 안 된다.
- 일시정지/창 전환은 게임 모션·월드 VFX·타이머를 함께 멈춘다. 메뉴 선택 반응은 별도 UI 시간으로 진행 가능하다.
- 재도전/장면 이동은 직전 사건의 파편·잔상·피격 HUD 타이머를 취소하고 새 상태를 그린다.
- 같은 노출 중 3타에 기존 노심 반응은 반복돼도 개방 모션/5.2초 노출 타이머는 초기화하지 않는다.
- 효과 대기 때문에 이동·점프·대시·다음 퍼즐 입력을 늦추지 않는다.

## 10. 제작 순서와 에셋 추가 판단

### P0 — 알아볼 수 있어야 하는 것

1. HUD/폰트/기본 UI의 640×360 배치 샘플 1화면. 한글 판독·정수 확대를 가장 먼저 검토.
2. 티크/보스 체력의 정상→피해→빈 칸, 실제 HP와 일치하는 표시.
3. 유효 타격 / 실제 장갑 접촉 / 허공 / 티크 피해의 구별.
4. 돌진·낙하 조준 추적/확정, 노심 노출/종료, 충전/노출 게이지.
5. 재도전·일시정지·최종 타격으로 상태가 꼬이지 않는지 검토.

### P1 — 손맛과 접촉을 보강할 것

짧은 주먹 호, 발 먼지, 대시 잔상, 공중 재추진, 충전 브리지/기둥 충돌, 낙하 충격, 추 마찰/구슬 정지.
본체 동작 기획과 함께 연결한다. 모든 버튼/키 캡·퍼즐 복구 안내를 같은 UI 키트로 완성한다.

### P2 — 시간이 남으면

제목 워드마크, 귀환의 작은 회로 전달 효과, 배경의 제한된 작동 불빛.
추가 배경 전체·컷신·큰 초상화·보스 단계별 별도 디자인·전면 폭발은 보류한다.
5–6분 게임에서 정보와 손맛을 먼저 완성하며 장식으로 플레이 시간을 늘리지 않는다.

### 사용자가 언급하지 않았지만 보충이 필요한 핵심

- **한글 픽셀 글꼴과 숫자/키 글리프:** 그림만 픽셀로 바꿔도 화면은 통일되지 않음.
- **버튼·패널·키 안내:** 기본 GUI 스타일이 가장 쉽게 남는 비픽셀 요소.
- **조준 확정과 약점 종료:** 피할 수 있는지/지금 때려도 되는지 판독에 직접 필요.
- **충전/노출 시간:** 생긴 기둥만 보아서는 언제 사라질지 알 수 없음.
- **티크 피해/보호/마지막 피해:** “맞았나?”와 “지금 또 맞을 수 있나?”를 분리.
- **착지·대시·무게 추 접촉:** 본체 움직임과 공간의 접점을 읽게 하는 공용 소규모 효과.
- **실수 복구 아이콘과 상태 정리:** 퍼즐 되돌리기에서 이전 효과가 성공 상태처럼 남지 않도록 함.

타격 소리도 함께 맞아야 손맛이 생기지만 소리는 픽셀 에셋이 아니다.
기존 hit/hurt/land 등을 우선 유지하고 **노심 성공·장갑 접촉·허공**의 오디오 구별만 별도 보충 후보로 적는다. 이 문서에서 새 음원 생성/구매는 하지 않는다.

### 사람과 함께 확인할 것

1. 소리를 끄고도 성공/장갑/허공/티크 피해를 구별하는가?
2. 처음 보는 사람이 HP 5칸·보스 9칸을 즉시 읽는가?
3. 조준 확정 후 회피, 노심 닫힘 후 공격 실패가 납득되는가?
4. 주먹 효과가 실제 공격보다 길어 보이지 않는가?
5. 효과 때문에 티크·노심·바닥 위험이 가려지지 않는가?
6. 픽셀 한글이 실제 플레이 크기에서 읽히고 UI가 너무 복잡하지 않은가?
7. 추·구슬·기둥의 기존 상태 아트와 신규 HUD/효과가 같은 게임처럼 보이는가?

자동 진행 성공은 재미·시각 승인의 증거로 쓰지 않는다.
먼저 P0를 넣은 짧은 전투를 사용자와 확인하고, “작게/빠르게/밝게” 같은 실제 피드백에 따라 효과 프레임과 수명을 조정한다.

**인계 산출물:** 에셋 작업표, 기존/신규 접촉 비교, 단일 참고 이미지, 네이티브 원본, PNG/Piskel/APNG/시간 JSON, 사건 연결표, 글꼴 라이선스, 검증 결과, 실제 화면 비교.

## 1. 핵심 방향

**고장난 운반 통로에서 첫 동력실로 떨어진 티크가 착지하고, 귀환 기록을 발견한 뒤 그 자리에서 플레이어가 첫발을 떼는 오프닝.**

최신 결정은 **AI 영상이 아니라 게임 안의 픽셀 낙하 연출**이다. 이전 정지 시작안을 대체한다. AI 생성은 필요한 단일 구도·소품·착지 포즈 참고에만 사용한다.

별도 영상·새 장소·새 인물·장시간 세계관 설명 없이 실제 게임 공간에서 연출한다.
낙하 종료의 발 접점은 기존 첫 퍼즐 시작 칸의 렌더 기준점과 일치한다. 오프닝 마지막 화면과 첫 플레이 화면은 같은 배경·캐릭터 크기·좌표를 사용한다. 퍼즐에 중력·낙하 피해·새 상자 물리를 추가하지 않는다.
자동으로 퍼즐을 풀거나 별도의 이동 튜토리얼 방을 거쳐 오지 않는다.

관객에게 전달할 정보는 세 가지다.

1. 이 작은 로봇이 티크다.
2. 돌아갈 곳은 엘리아스 공방이다.
3. 귀환 회로 세 곳이 끊겼다. 내가 연결해야 한다.

폐기 장치의 세부 규칙과 보스 전체 실루엣은 이때 설명하지 않는다.
퍼즐 복구로 문지기가 깨어나는 반전을 섹션 전환에서 보여 준다.
기억코어 복원·새 능력 획득·엘리아스의 등장/생사 등 새로운 설정은 넣지 않는다.

## 2. 짧은 문구와 감정

오프닝에 새로 확정할 화면 문구 후보:

- 시설 기록: **“귀환처: 엘리아스 공방.”**
- 시설 기록: **“귀환 회로: 연결 0 / 3.”**
- 티크의 작은 독백: **“…돌아갈 수 있겠네.”**

문구는 연출 때 순서대로 보여 주고, 첫 조작 후에는 필요한 목표만 남긴다.
풀 보이스·긴 대화창·긴 타자 효과 없이 바로 완성된 짧은 글자를 표시한다.
가벼운 전원음/하트 모티프는 보충 후보이며 기존 소리를 우선한다. 소리 없이도 이해되어야 한다.

감정 흐름은 **갑자기 떨어짐 → 잠깐의 적막 → 작은 희망 → 직접 복구하는 성취 → 내가 깨운 위협 → 귀환 허가**다.
오프닝에서 공방으로 이미 귀환한 것처럼 공간을 설명하지 않는다. 현재 장소는 끊긴 귀환 회로가 있는 시설이다.

마스크는 부드러운 전체 화면 알파 페이드 대신 이산 단계의 검정 도트/직사각형 가림을 사용한다.
과도한 스캔라인·빠른 점멸은 넣지 않는다. 착지 때만 최대 1 네이티브 픽셀·60~80ms의 짧은 흔들림을 선택적으로 검토한다. 효과 감소에서는 흔들림을 생략한다.
오프닝 종료 때 새 퍼즐 씬을 로드해 깜빡이거나 캐릭터 위치가 뛰지 않도록 한다.
배경에 아직 없던 기록 패널은 작은 HUD/회로 UI 표현으로 보충하고, 첫 퍼즐 지형을 다시 그리지 않는다.

### 낙하 렌더링·좌표 계약

현재 퍼즐 렌더링은 bx=194, by=64, cell=36을 사용한다.
첫 시작 칸의 player 좌표에서 티크 발 기준은 **x=bx+(player%7)*cell+18, y=by+(player/7)*cell+32**로 계산된다.
이 계산은 기존 렌더러의 공통 변환으로 재사용하고 별도 상수 복사본을 만들지 않는다. 전투의 hero.x=80/Floor 좌표로 착지시키지 않는다.

오프닝에서만 drawY = spawnFootY + openingDropOffset을 사용한다. 화면 밖 음수 오프셋→가속된 하강→0 접지로 진행한다.
시작 y/시간으로 낙하 속도를 설계하고 실제 게임 픽셀 이동을 검토한다. 퍼즐 논리 player/boxes/goals는 처음 상태 그대로다.
오프닝의 카메라/깊이 정렬이 상단 벽 뒤로 티크를 숨기지 않는지 확인하고, 손·발이 통로 프레임과 겹쳐 끊기지 않게 한다.
이동 통로 표시는 배경/전경 장식이고 충돌·새 문·스위치 기능을 추가하지 않는다.
Title에는 같은 티크를 시작 칸에 미리 그리지 않는다. 캐릭터를 중복 생성해 낙하 티크와 Idle 티크가 동시에 보이면 안 된다.
낙하 완료로 바닥 영구 균열/물체 밀림/카메라 맵 이동을 만들지 않는다.

## 5. 첫 퍼즐을 자연스럽게 시작시키는 방법

첫 방의 기존 판 배치·정답·난이도를 바꾸지 않는다.
오프닝에서 추를 자동으로 소켓에 넣거나 정답 경로를 보여 주지 않는다.
처음에는 **방향키 이동과 추/소켓 모양의 대응**만 알려 준다. 구슬 규칙은 기존 두 번째 방에서 소개한다.

조작권 전달 후 보조 안내 후보:

- 한 줄 목표: “추를 밀어 같은 소켓에 놓으세요.”
- 키 안내: “방향키 이동 / Z 되돌리기 / R 초기화 / H 힌트”
- 첫 추와 대응 소켓에 작은 고정 모서리 표식. 정확한 해답 칸이나 밀 순서는 강조하지 않는다.

첫 이동은 전용 튜토리얼 테스트가 아니다. 실제 첫 퍼즐의 정상 이동 이력/수에 기록한다.
첫 성공한 이동·밀기 뒤에는 첫발 안내를 줄이고 목표/복구 키만 유지한다.
오래 기다려도 안전하다. 위험·시간 제한·자동 이동을 넣지 않고 H 힌트를 선택할 수 있게 한다.

## 6. 퍼즐→전투→엔딩 연결

### 마지막 회로 완료

1. 마지막 물체가 실제 화면에서 도착하고 기존 socket-connect를 재생한다.
2. 기존 완료 800ms 안에서 회로 3칸/배경 불빛이 완성된다. 소켓 도착 전에 연출 카드가 가리지 않는다.
3. 기존 완료 확인 Enter로 전투실에 진행한다. Enter를 누르기 전 자동 전환하지 않는다.
4. 집행실에서 2~3초 이내의 짧은 장치 기동: 전력 수신→지지 잠금. 문구 후보는 “귀환 동력 복구.”, 이어 “폐기 집행 장치 재가동.”
5. 이후 전투 안내를 고정하고 **새 Enter 입력**을 기다린다. “기둥 E 충전→돌진 유도→열린 노심 X 공격”, “파형은 점프 / 낙하는 대시”.
6. 확인 후 TB01/GB04에서 기존 휴식·예고를 거쳐 첫 공격. 안내 중 공격 타이머/파형/접촉 피해 없음.

모션 기동 시간과 사람이 설명을 읽는 대기 시간을 분리한다.
퍼즐 완료에 썼던 Enter가 전투 안내까지 동시에 넘기지 않도록 구간마다 release 후 새 입력을 요구한다.
문지기 재도전은 완료 퍼즐을 유지하고 짧은 전투 준비/안내 확인만 한다. 첫 기동 2~3초를 강제로 반복하지 않는다.

### 엔딩의 회수

현재 귀환문 800ms 개방 및 문 앞 E 확인은 유지한다.
엔딩에서 “식별명: 티크. 귀환처: 엘리아스 공방.”과 기존 귀환 허가/작은 하트 문구로 오프닝의 기록을 회수한다.
문지기를 전원 차단시켰는데 정상화된 본체가 다시 움직여 신원 검사를 하는 새 컷신은 넣지 않는다. 기존 시설 기록 확인으로 마무리한다.
새 공방 배경·엘리아스 초상·귀환 이동 맵·추가 미니게임은 만들지 않는다.

초기 분량은 오프닝 14초, 재가동 약 2초, 짧은 엔딩 판독 약 8~10초 수준이다.
안내 대기는 사용자마다 다르므로 전체 체험 시간을 실제로 측정한다. 이 연출을 더해서 5~6분을 보장한다고 보고하지 않는다.

## 7. 입력·skip·일시정지 상태 계약

제안 흐름: Title → Opening → Puzzle → RoomClear … → Arrival의 기동/안내 → Combat → Restored → Ending.
현재 소스에는 Journey.Opening이 없다. 새 상태 또는 동등한 하위 연출 상태를 추가하는 **구현 제안**이다.
별도 영상 플레이어/타임라인 패키지는 필수가 아니며 기존 모델의 상태·사건 구조를 우선한다.

- Title의 Enter는 시작만 한다. 같은 프레임/눌림 유지로 Opening까지 skip되지 않게 release+새 key-down을 요구한다.
- Opening에서 새 Enter 입력은 “첫 방으로 건너뛰기”. 작은 픽셀 안내를 표시한다. skip은 O08과 동일한 최종 상태를 한 번만 만든다.
- Z/X/C는 skip에 사용하지 않는다. 퍼즐 Z 되돌리기나 미래 전투 입력과 충돌하지 않게 한다.
- skip/end 시 pending 입력, 누른 키 상태/버퍼, 누적 프레임 시간, 연출용 임시 효과·소리 예약을 정리한다. 넘어온 방향키가 첫 칸을 멋대로 밀지 않게 한다.
- 조작권은 새로운 입력을 받을 준비가 끝난 시점에 넘긴다. 자연 종료와 skip 후 실제 첫 칸/물체/소켓/이력/0회 카운트가 동일해야 한다.
- Esc/pause/focus-loss는 연출 시간·눈 깜빡임·텍스트·소리 예약을 정지한다. 복귀 즉시 마지막 5초를 몰아서 재생하지 않는다.
- “처음부터”는 초기 상태를 완전히 만들고 Title로 돌아간다. Opening이 여러 개 겹쳐 재생되거나 기록/힌트가 이전 회차 상태로 남지 않게 한다.
- 재도전은 Opening으로 돌아가지 않는다. 퍼즐 완료 체크포인트 유지.
- 기존 playTime 표시의 포함 범위를 먼저 조사하고 명시한다. Opening 시작/종료/skip 시각을 별도 사건으로 기록하여 연출·조작·안내 대기를 구분한다. 알 수 없는 시간을 플레이 시간에서 임의로 빼지 않는다.
- 자동 검사도 일반 시작/skip/확인 입력 경로를 사용한다. 테스트에서 상태를 직접 Puzzle/Combat으로 바꾸어 연출 경로를 검증했다고 하지 않는다.

**공용 제작 규칙:** 낙하 먼지와 일반 착지·대시·추 마찰은 동일 계열 도트를 공유한다.
낙하가 무거워 보이게 할 때는 먼지 개수·노출 시간·소리로 조절하고 티크 크기/팔 길이를 늘리거나 새 피해를 추가하지 않는다.
기존 검증에서 현재 독립 착지 먼지 자산은 확인되지 않았으므로 구현 PC에서 실제 파일을 다시 검사한다. 이미 추가된 것이 있으면 중복 제작하지 않는다.

**제작 순서:**

1. DO-A01/02 원본 크기 접촉 비교와 사용할 구간·시간을 기록한다.
2. 실제 첫 방에서 임시 오프셋 낙하→접지→Idle 인계를 먼저 구현해 좌표를 확인한다.
3. 발 접점에 맞는 DO-A03/04 샘플을 만들고 필요할 때만 DO-A05 장식을 보충한다.
4. 이미지 생성이 필요하면 해당 환경의 imagegen 스킬을 읽고 **통로/착지/먼지의 단일 참고 이미지**를 만든다. AI 영상·애니메이션 시트는 납품물로 사용하지 않는다.
5. 기준 도트의 정수 좌표 편집으로 최종 픽셀 프레임 제작. PNG·가변 시간 JSON·Piskel·APNG·픽셀 변경 기록 보존.
6. 접지 사건 1건에 먼지·그림자·착지 모션·소리를 연결하고, 기록 표시/skip/인계/재시작에서 중복 재생을 검사한다.

입자가 바닥에서 튀는 동안 3D 파티클이나 소프트 파티클 셰이더를 새로 도입하지 않는다. 픽셀 스프라이트/프레임으로 처리한다.
640×360·Point·정수 배율·이진 원본 알파·팔레트 계약을 유지한다.
영상용 새 배경·별도 기상 애니메이션·카메라 줌용 큰 티크·엘리아스 초상·공방 전체·운반 레일 물리/파괴 시스템은 필요 없으므로 제작하지 않는다.

## 9. 검증·사람에게 물을 질문

기술 검사:

- 새 게임에서 Title→Opening→Puzzle가 한 번씩 진입하고 첫 방 상태가 그대로인가?
- 자연 종료와 낙하 전/낙하 중/접촉 순간/먼지 소멸 중/기록 표시 중 skip 후 첫 방/물체/카운트/입력 버퍼가 같은가?
- 착지 발 접점이 첫 퍼즐 렌더 좌표와 일치하며, 티크/먼지/착지음이 중복 생성되지 않는가?
- 낙하 속도와 프레임이 맞고, 기존 Jump의 상승/발차기 자세가 섞이거나 전투 바닥으로 착지하지 않는가?
- Title의 티크 선행 노출, 낙하 피해/보호 부여, 퍼즐 이동 수 증가, 물체 변형이 없는가?
- Enter 누른 채 유지/연속 입력/방향키 유지로 시작·skip·첫 이동·전투 시작이 동시에 발생하지 않는가?
- Opening 중 pause/focus-loss, skip 직후 pause, “처음부터”에서 효과·소리가 중복되지 않는가?
- 첫 성공한 이동은 실제 퍼즐에 기록되고 실패한 벽 입력은 첫발 완료가 아닌가?
- 마지막 소켓→800ms 완료→확인→기동→안내 확인→첫 공격의 순서를 실제 입력으로 지나가는가?
- 문지기 재도전에서 오프닝/퍼즐/긴 기동을 다시 요구하지 않는가?
- 처음부터 엔딩까지 일반 입력 자동 검사와 직접 입력에서 새 연출 경로를 확인했는가?
- 720p/1080p/비정수 창/고DPI에서 글·마스크·캐릭터 기준점이 읽히고 HUD 인계 때 화면이 튀지 않는가?

사용자에게 확인할 질문:

1. 설명 없이도 “공방으로 돌아가려면 세 회로를 고쳐야 한다”를 이해했나?
2. 떨어져 착지한 바로 그 티크를 내가 움직이는 느낌인가? 낙하가 장식 영상처럼 분리되지 않았나?
3. 퍼즐 복구가 문지기를 깨웠다는 원인이 읽히나?
4. 오프닝이 짧고 도움이 되는가, 다시 볼 때 skip을 바로 이해하는가?
5. 귀환 허가가 처음의 귀환처 기록에 대한 작은 결말로 느껴지는가?

자동 검사 성공을 서사 전달/재미 승인으로 대신하지 않는다.
이 문서는 연출 기획과 인계 요구사항이며 현재 게임에 적용됐다는 보고가 아니다.

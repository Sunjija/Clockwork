# 다른 PC 작업 프롬프트 — 티크 최소 동작 구현

Sunjija/Clockwork의 「티크: 귀환 회로」 Unity v0.4를 이어서 작업해줘. 목표는 승인된 두 섹션 최소 동작 기획을 실제 플레이 가능한 애니메이션과 상태 전환으로 구현하고, 실행해서 검증하는 것이다.

저장소: https://github.com/Sunjija/Clockwork
프로젝트: unity/TiqueReturnPrototype
현재 씬: Assets/Scenes/TiqueReturnV2.unity
Unity 기준 버전: 6000.5.3f1

먼저 작업 환경의 변경 사항과 AGENTS.md를 확인하고, origin/main의 최신 내용을 받아 작업 기준을 맞춰라. 기존 작업이 있으면 보존하고 별도 작업 브랜치나 체크아웃에서 진행한다. 저장소가 아직 없으면 clone한다. main에 기획 문서가 포함되어 있는지 확인한다.

## 구현 범위

섹션 1은 공간 퍼즐 3방, 섹션 2는 철갑 문지기 전투와 귀환이다. 문지기는 섹션 1에서 본체가 등장하지 않는다. 회로 복구가 섹션 2 재가동의 원인이 되도록 연결한다.

기획서의 103개 ID는 티크 공통 8개, 퍼즐 22개, 전투 34개, 문지기 39개의 행동·판정 구간이다. 기존 클립 부분 재생, 특정 자세 유지, 같은 사건에 겹치는 동작을 포함한다. 이를 103개의 신규 클립으로 만들지 마라.

각 ID에 현재 대응하는 상태/프레임, 부족한 표현, 적용할 전환과 판정, 재사용 또는 신규 제작 여부를 적은 작업표를 먼저 작성해라. 표가 작성되면 아래 순서로 실제 구현을 진행한다. 통상적인 설계 선택마다 확인을 기다리지 말고 승인된 기획 범위에서 작업을 끝까지 진행한다.

1. 티크 추 밀기·구슬 방출: 손 접촉, 지지 발, 힘 전달, 손 놓기, 물체 도착을 구별한다. 추 이동은 150ms, 구슬 이동은 270ms 기준을 유지하고 준비 모션으로 조작 지연을 추가하지 않는다.
2. 티크 피격·복귀·실패: 피해 순간을 읽히게 하면서 기존 1.1초 보호 중 조작을 유지한다. 강제 넉백이나 긴 경직을 임의로 추가하지 않는다.
3. 문지기 충돌·노심: 일반 벽 제동, 충전 기둥 충돌, 장갑 열림, 노출 유지, 피격, 장갑 닫힘을 분리한다. 노심이 맞을 때마다 본체 개방 모션이나 노출 타이머가 재시작하지 않게 한다.
4. 티크 기둥·귀환문 접촉, 문지기 기동·전원 차단, 강화 충격파/낙하 예고를 보완한다.
5. 기본형 유지 + 눈만 깜빡임을 적용한다. 현재 Unity Idle은 정적 1장이므로 이미 적용돼 있다고 가정하지 않는다.
6. 입장 안내는 사용자가 Enter로 확인한 뒤 첫 공격이 시작되도록 한다.
7. 전투키는 사용자가 지정한 Z/Space/↑ 점프, X 공격, C 대시, 방향키 이동으로 통일한다. E 충전·문 조작은 유지한다. 퍼즐은 방향키/WASD 이동, Z/Backspace 되돌리기, R 초기화, H 힌트를 유지한다. 섹션별 입력 분기와 화면 안내를 함께 맞춘다. 기획서에 적힌 Space/J/Shift는 v0.4의 변경 전 기록이다.

그 외 전투 체력, 피해, 이동 속도, 예고, 반격 시간을 임의로 재조정하지 않는다. 첫 플레이 5~6분은 사람과 검증할 목표이며, 자동 진행 시간이나 체력 증가로 달성했다고 판단하지 않는다.

## 아트·애니메이션 제작 계약

티크와 문지기 모두 티크에서 확립한 동일한 제작 과정을 적용한다.

- 기준 도트, 비율, 팔레트, 기준점과 접지 발을 잠근다. 티크는 64×64·(32,56), 문지기는 192×144·발 기준선 132px를 확인한다.
- 이미지 생성이 필요한 경우 해당 환경의 imagegen 스킬을 읽고, 동작별 단일 참고 이미지를 먼저 만든다. 생성 결과는 참고용과 기준 도트를 구분한다.
- 최종 프레임은 승인한 기준 도트의 픽셀 덩어리를 정수 좌표로 옮기고 연결부를 픽셀 편집하는 방식으로 제작한다.
- AI로 완성 애니메이션 시트를 생성한 뒤 잘라 쓰거나, 프레임마다 전체 캐릭터를 다시 생성하지 않는다. 런타임 본체 부품 리깅으로 바꾸지 않는다.
- 기존 티크 기본형과 사용자가 선택한 뒤쪽 팔 공격을 보존한다. 팔 늘리기, 체형 변화, 머리·몸통을 이유 없이 흔드는 대기를 피한다.
- 투명 PNG, 가변 프레임 시간 JSON, 편집 가능한 Piskel, APNG, 픽셀 변경 기록을 보존한다. Piskel의 20FPS 편집 재생은 정확한 런타임 타이밍과 구분한다.
- 기존 67장 티크·52장 문지기 원본은 비교·보존할 수 있게 둔다. 새 동작 또는 재생 구간을 명시하고 기존 검증을 무의미하게 완화하지 않는다.
- 조준 확정·기둥 충돌·타격·착지·소켓 접속·문 개방 사건에 그림과 효과를 연결한다. 보스는 예고 뒤 발동하고, 티크는 성공한 입력 즉시 움직인다.
- 실제 적용한 제작 방식과 도구를 기록한다. 코드로 픽셀 좌표를 편집했다면 그렇게 설명하고, Piskel UI에서 직접 그렸다고 주장하지 않는다.

## 실행·검증·완료 조건

현재 PC의 Unity 설치·라이선스·플랫폼 지원을 확인하고 그 PC에서 플레이 가능한 빌드를 만든다. Windows는 기존 Tools/Build-Windows.ps1을 우선 사용한다. Mac이면 해당 플랫폼 빌드와 설치된 한글 폰트 선택을 확인한다. 이 저장소에는 이전 PC의 실행 파일, Unity Library, 로컬 Mac 빌드 변경이 포함돼 있지 않다.

현재 모델·아트 검사를 실행하고 새 동작에 필요한 실제 전환·접촉·시간 검사를 보완한다. 기존 자산 보존 검사를 유지한다. 일반 입력 경로의 퍼즐 3개 → 보스 → 엔딩 자동 진행, 실제 키 입력, 되돌리기·초기화, 점프/대시/공격 취소, 피격/재도전, 창 전환 일시정지, 한글 표시를 검증한다. 자동 입력으로 확인한 범위와 직접 키 입력으로 확인한 범위를 구분한다.

원본 크기·느린 재생과 실제 플레이 화면에서 손·물체 접점, 발 접지, 노심 위치, 조준 확정, 명중/빗나감, 전원 차단·귀환문 개방을 확인한다. 기술 검사를 사람의 재미나 최종 아트 승인으로 표현하지 않는다.

원본·작업표·검증 결과·제작 기록을 저장소에 저장한다. 마무리 보고에는 적용된 ID 묶음, 신규/재사용 자산, 실행 방법, 확인한 범위, 미해결 사항, 사용자가 직접 검토할 장면을 적는다. 실행 가능한 최종 빌드를 열고 사용자가 처음부터 직접 플레이할 수 있는 시작 화면으로 넘겨줘.

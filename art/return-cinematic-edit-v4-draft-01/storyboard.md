# 티크 연출 구조 v4 — 복구, 위협, 정지, 상승

사용자 수정 반영: **공방·목적지는 보여주지 않는다. 마지막은 엘리베이터 탑승·상승만.** 영화적인 리듬은 새로운 사건이나 캐릭터 포즈가 아니라 샷 크기와 시점 선택으로 만든다.

상태: 도트 편집본 후보 제작. 사용자 구도·리듬 승인 및 게임 연동은 별도다. 기존 낙하 오프닝·게임 조작·퍼즐·보스 패턴은 변경하지 않는다.

## 전체 게임 안에서의 구조

| 구간 | 역할 | 카메라·조작 원칙 |
|---|---|---|
| 기존 낙하 오프닝 | 티크가 떨어져 시작 | 현재 낙하 연출 유지. 이번 재편집 대상 아님. |
| 퍼즐 플레이 | 설비를 복구한다 | 플레이 중에는 가독성을 위한 기존 카메라. 임의 클로즈업으로 입력을 방해하지 않는다. |
| 마지막 복구→문지기 기동8초 | 성공이 위험을 깨웠다는 원인·결과 | 복구 관계샷 → 전력 인서트 → 노심 → 전투 전체. |
| 실제 보스전1·2페이즈 | 직접 대응한다 | 전투 중 기본 와이드 유지. 패턴/HP/재시도는 이번 변경 대상 아님. |
| 처치 확정→쓰러짐3초 | 위험 해소를 보여준다 | 몸이 내려앉음 → 꺼진 노심 → 티크와 보스 전체. |
| 조작 복귀·승강기 접근 | 플레이어가 다음 이동을 선택 | 엘리베이터 사용 가능. 재편집본의 탑승 자동이동은 시청용이며 실제 접근·상호작용 게이트는 연동 시 구현. |
| 엘리베이터7초 | 이동 자체로 마무리 | 탑승 → 접점/가이드 → 탑승자 → 샤프트 전체·위로 이탈. 목적지는 비공개. |
| 엔딩 메뉴 | 종료 | 상승 종료 후 연결. 공방·하차·도착 자막 없이. |

기동8초·쓰러짐3초·엘리베이터7초는 **서로 다른 게임 시점의 독립 클립**이다. 통짜18초 영화가 아니다. 보스전과 플레이어의 승강기 접근 시간이 사이에 있다.

## 세 줄 이야기

티크가 복구한 전원이 잠들어 있던 문지기를 깨운다.  
문지기를 멈춘 티크는 엘리베이터에 오른다.  
차가운 공장을 뒤로하고 올라가는 모습에서 이야기를 닫는다.

공방이 목적지일 수 있다는 기존 설정을 부정하는 것이 아니라, **관객에게 그 공간을 보여주는 컷을 없앤다.** 새 장소나 후속 사건을 추가하지 않는다.

## A. 기동 — 8초, 4샷

| 샷 / 시간 | 크기 | 무엇을 보여주나 | 컷의 이유 |
|---|---|---|---|
| A1 · 0–2초 | 복구 미디엄·관계샷 | 티크, 손잡이 황동 추, 사각 소켓과 회색 벽. 청록 원형 구슬도 남긴다. | 방 전체보다 ‘내가 무엇을 연결했는가’에 집중. |
| A2 · 2–4초 | 릴레이 CU | 기존 릴레이가 닫히고 청록 전력이 전달된다. | 방금 복구한 설비의 다음 원인. 기존 실제 생성/도트 프레임 재사용. |
| A3 · 4–6초 | 입속 노심 ECU | 붉은 노심·턱 피스톤 기동. | 청록의 성공에서 붉은 위협으로 전환. 얼굴·눈을 새로 만들지 않는다. |
| A4 · 6–8초 | 전투 와이드 | 왼쪽 티크, 오른쪽 문지기. 기존 ‘폐기 대상 감지’. | 위협의 대상과 거리를 읽힌 뒤 게임 카메라로 정확히 돌아온다. |

기존 A2/A3는 이미 필요한 클로즈업이었다. 다시 생성하거나 새 사건을 추가하지 않고 유지했다. A1만 원본 세계의320×180 영역을 정수2배로 확대했고, A4는 기존640×360 화면 그대로다.

## C. 쓰러짐 — 3초, 3샷

| 샷 / 시간 | 크기 | 화면·동작 | 의도 |
|---|---|---|---|
| C1 · 0–0.85초 | 문지기 미디엄 | 서 있는300ms 뒤 원래 defeat00–04가 각110ms 진행. 몸이 내려앉는다. | 보스 전체의 낙하를 놓치지 않는다. |
| C2 · 0.85–1.8초 | 꺼진 입속 CU | 기존 defeat05의 입속이 꺼진 상태. 움직임 추가 없음. | 기동에서 본 붉은 노심에 대한 시각적 답. |
| C3 · 1.8–3초 | 전투 와이드 | 왼쪽 티크·오른쪽 정지한 보스. 기존 문은 닫힌 채. | 위험 해소와 게임 복귀를 함께 정리. 승리창으로 가리지 않는다. |

쓰러짐을 컷마다 다시 재생하지 않는다. 원본3초 타임라인에서 카메라만 자른다. 문지기를 옆으로 회전시키거나 넘어지는 새 포즈를 생성하지 않는다.

## E. 엘리베이터 — 7초, 4샷

| 샷 / 시간 | 크기 | 화면·동작 | 의도 |
|---|---|---|---|
| E1 · 0–1.2초 | 탑승 미디엄 | 티크의 기존 Walk760ms로 좌→우 탑승, 남은440ms 정지. | 어디에 들어갔는지 공간을 먼저 읽힌다. |
| E2 · 1.2–2.2초 | 설비 인서트 CU | 기존 승강기 오른쪽 가이드·청록 상태등과 레일. 상승이 시작된다. | 사람이 아닌 기계 접점으로 시작 동작을 강조. 없는 버튼 누르기 포즈를 만들지 않는다. |
| E3 · 2.2–4.6초 | 탑승자 클로즈·수직 트래킹 | 티크와 같은 차체를 따라가고 뒤의 벽·레일이 내려간다. 기존 눈 깜빡임 한 번. | 이동 속에서 티크에 집중. 눈동자 방향·표정·몸체는 새로 그리지 않는다. |
| E4 · 4.6–7초 | 샤프트 와이드 | 고정 화면에서 같은 승강기가 위쪽으로 계속 올라가 화면 밖으로 이탈.6.6초 하드 컷 투 블랙,400ms 홀드. | 목적지를 보여주지 않고 ‘이곳을 떠났다’로 끝낸다. |

이 네 컷은 **단일 상승 동작의 연속 편집**이다. 컷 사이에 세계 좌표·속도·눈 깜빡임 시계를 초기화하지 않는다.1.2–6.6초에 발판 y282→−32로 하나의 quadratic ease-in 곡선을 적용한다. 화면 밖 이탈은 E4에서 의도된 클리핑이며, 뒤틀림·모핑·가짜 배경 연장이 아니다.

배경의 상부 공방·상부 착륙층을 실제 이미지 생성 편집으로 전부 제거했다. 마지막 공방 컷만 잘라낸 것이 아니다. 작업등·작업대·시계·하차·착륙·도착음·‘돌아갈 곳이 있어.’ 자막은 최신 편집본에서 사용하지 않는다.

## 카메라 규칙

- **축은 유지하고 거리만 바꾼다.** 티크의 좌→우 탑승, 수직 상승을 유지한다. 측면 세계를 갑자기 정면·반대편 시점으로 바꾸지 않는다.
- 크기는 와이드640×360, 미디엄320×180→2배, 클로즈160×90→4배. 컷 전체에 NEAREST 정수 확대를 적용한다. 소스 스프라이트나 특정 몸체 부위를 따로 확대하지 않는다.
- 트래킹은 정수 카메라 좌표만 사용하며 원본640×360 내부에서 움직인다. 밖에 배경을 반복·합성·그려 늘이지 않는다.
- 자르기는 원인 전달·정지 확인·움직임 강조·조작 복귀가 필요한 지점에만 한다. 쓸데없는 흔들림·줌 왕복·강한 전환 효과를 넣지 않는다.
- 조작 가능한 퍼즐/전투에는 이 영화식 클로즈업을 강제로 적용하지 않는다.

## 이미지 우선·동작 재사용

새 샤프트는 내장 이미지 생성 → 생성 원본 표시·메인 검수 → 논리320×180 BOX·기존64색 팔레트 → NEAREST2배 native640×360 순서다. 실제 생성 그림에 없는 형상을 코드로 대신하지 않았다.

기존 이미지-first 승강기128×128, 티크64×64/등록점(32,56), 문지기192×176/등록점(96,164), A2/A3 동작을 재사용했다. 몸체·알파·팔레트·원본 PNG는 보존했고, 영화 샷 크기는 완성된 세계 전체의 카메라 크롭에서 만든다. 기술 검증은 사용자의 외형·연출 승인과 별개다.

## 연동 시 지켜야 할 것 — 아직 미구현

전투 종료 상태와 컷 재생 상태를 하나의 처치 흐름으로 관리해 defeat가 두 번 실행되지 않게 한다. C3는 현재 게임 위치와 매치한 뒤 입력을 복귀시킨다. E는 실제 승강기 상호작용 뒤 시작하고,6.6초 투 블랙 뒤 종료 상태/메뉴로 연결한다. 각 클립은 스킵 가능하며 확정 입력을 소비한다. 재시도·2페이즈 단독 시작에서 엔딩을 재생하지 않는다.

이번 작업은 게임·오프닝·SFX를 변경하거나 실행하지 않았다. v3의 도착/시계 임시 WAV는 최신 편집본에 연결하면 안 된다. 기동 SFX도 클립별로 재동기화해 사용하는 단계가 남아 있다.

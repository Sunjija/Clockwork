# 티크 직접 조작 장면 제작 기록

## 요청과 적용 범위

기존 동작 실험실의 버전 선택, 프레임 목록, 타임라인, 배율·방향 선택, 반복 재생, 비교·다운로드 링크를 주 화면에서 제거했다. 동일한 URL이 이제 림부스 배경의 직접 플레이 장면으로 열린다. 기존 검수 화면은 `티크-동작실험실-검수기록.html`에 보관했다.

새 게임의 스토리·전투 규칙을 확정하는 작업이 아니라, 기존 티크 동작을 직접 조작하는 장면이다. 적과 피해 판정은 없으며 J는 선택된 공격 애니메이션을 재생한다.

## 조작

| 입력 | 동작 |
|---|---|
| ← / → | 좌우 이동, 진행 방향으로 캐릭터 반전 |
| Space 또는 ↑ | 점프, 공중에서 한 번 더 눌러 더블점프 |
| Shift | 바라보는 방향으로 대시 |
| J | 뒤쪽 팔 공격, 공중에서도 중력 유지 |
| Esc | 일시정지 / 계속 |
| R 또는 처음 위치로 | 시작 위치로 복귀 |

좁은 화면과 터치 기기에는 이동·공격·대시·점프 버튼을 제공한다. 키 자동 반복으로 더블점프나 공격이 중복 실행되지 않으며, 창 전환 시 정지하고 누른 키를 초기화한다.

## 물리와 애니메이션 연결

- 640×360 장면, 1/120초 고정 물리 간격. 30/60/144Hz 렌더링에서 같은 이동 결과를 검사했다.
- 기존 컨트롤러는 y=0 하나만 바닥으로 취급했고 지상 대시 종료 시 같은 높이로 돌아갔다. 새 컨트롤러는 실제 발판 상면과 발 위치로 접촉을 판정한다.
- 바닥 y=252, 발판 높이 y=228 / 202 / 228. 발판은 아래에서 통과해 위에 착지하는 방식이다. 눈에 보이는 상단 경계와 충돌 높이를 일치시켰다.
- 코요테 타임 120ms: 발판을 걸어 나간 직후 첫 점프를 허용한다. 이때 더블점프 기회도 유지한다. 시간이 지나면 공중 점프 한 번만 남고, 세 번째 점프는 불가능하다. 판정 해상도는 물리 틱 약 8.33ms다.
- 점프 입력 버퍼 100ms: 두 번 점프한 뒤 착지 직전에 누른 입력을 착지 시 한 번만 실행한다. 기한이 지난 입력은 소멸한다.
- 이동 42px/s. 원래 걷기의 25px/s 기준에 맞춰 실제 이동 거리로 프레임 시간을 진행해 발의 재생 속도를 연결했다. 전체 스프라이트를 변형하지 않는다.
- 점프 초기 속도 220px/s, 더블점프 205px/s, 중력 800px/s². 기존 값 유지.
- 대시 260px/s, 활성 목표 160ms, 재사용 최소 간격 300ms. 공중에서는 착지 전 한 번만 가능하다. 발판 밖으로 대시하면 실제 위치에서 낙하한다.
- 지상 공격 중에는 발 위치를 고정하고, 공중 공격 중에는 중력과 수평 조작을 유지한다. 점프·대시는 공격을 취소할 수 있다.
- 착지 때 짧은 착지 프레임을 거친 뒤 원래 기본형으로 복귀한다. 걷기 입력은 즉시 반응한다.

## 이미지 보존과 화면 정리

선택한 revision 10의 원래 기본형 Idle, 걷기, 뒤쪽 팔 Attack, Jump, DoubleJump, Dash를 그대로 사용했다. 이미지 자체의 머리·팔·하트 위치나 도트는 수정하지 않았다. 배경은 기존 림부스 컨셉, 발판은 기존 IndustrialRuins 타일을 복사했다. 출처와 해시는 `Scene/provenance.json`에 기록했다.

첫 화면 확인에서 발판 상단 타일의 투명 영역이 충돌 면을 끊어 보이게 해 채움 타일과 연속된 상단 선으로 수정했다. 원본 수정 시각을 보존하는 파일 복사 때문에 이전 타일이 브라우저 캐시에 남을 수 있어 최종 채움 타일은 별도 파일명으로 연결했다. 데스크톱에서 생긴 16px 세로 넘침은 화면 높이를 반영한 장면 너비 제한으로 해결했다.

Impeccable distill/polish 기준으로 주 행동인 플레이에 화면을 집중했다. 작은 제목과 키 안내의 글자 크기가 비슷하다는 자동 경고는 의도적인 예외로 남겼다. 이 화면의 시각적 중심은 배경과 캐릭터이며 큰 제목을 추가하지 않는다. 자동 탐지기는 HTML 파서 의존성이 없어 정규식으로만 실행됐으므로 깨끗한 전체 검사로 주장하지 않는다.

## 검증

`QA/play-controller.json`: 11개 자동 검사 통과. 좌우 이동과 경계, 코요테 타임 만료 전후, 점프 버퍼와 만료, 발판 밖 대시와 공중 재사용 제한, 빠른 낙하의 발판 관통 방지, 공중 공격 중력, 키 반복·초기화, 프레임 유효 범위, 화면 주사율 독립성을 포함한다.

브라우저에서 1280×800과 390×844를 확인했다. 수정 후 두 크기 모두 문서 너비·높이가 뷰포트와 같아 스크롤 넘침이 없었다. 모바일 버튼은 최소 48×44px이다. Space 점프, J 공격, Shift 대시 및 Esc 일시정지는 실제 키 입력과 화면에 그려진 상태의 DOM 기록으로 확인했다. 매우 짧은 자동 방향키 입력은 물리 틱 사이에 종료돼 이동 증거로 사용하지 않았으며, 지속 좌우 이동은 컨트롤러 자동 검사로 검증했다. 브라우저 오류·경고 로그는 없었다. 사용자 체감 승인은 별도다.

## 파일과 재현

- `Scene/play-controller.js`: 플랫폼 물리, 코요테 타임, 입력, 동작 선택.
- `Scene/play-scene.js`: 이미지 로드, 키·터치 이벤트, Canvas 표시, 창 전환 정지.
- `work/tique-action-set/play.html`: 단순화된 화면 원본.
- `python work/tique-action-set/build_play.py`: 같은 플레이 URL로 빌드. 원본 배경 경로가 있는 워크스페이스에서 실행.
- `node work/tique-action-set/play-check.cjs`: 자동 검사. 패키지에서는 `node Tools/play-check.cjs`도 사용 가능.
- `QA/play-source-preservation.json`: 이전 리비전 파일의 해시 보존 검사.

장면은 HTTP 서버로 열어야 한다. 현재 서버는 outputs 디렉터리를 127.0.0.1:8773으로 제공한다.

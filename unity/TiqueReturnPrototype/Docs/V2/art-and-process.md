## 티크의 기준을 다시 확인

`prototypes/tique-playground/Docs/process-history.md`의 최신 선택 이력을 읽었다. 대기08은 최초 기본형을 그대로 사용하고, 오른손09는 제외, 뒤쪽 팔 공격10을 복원했다. 현재 게임의 티크는 `Revisions/10/data.json`과 67 PNG를 그대로 사용하는 버전이다. 초기 걷기의 머리·하트 경계 수정 결과도 그 프레임에 포함된다.

이번 작업에서 티크의 머리·몸통·팔다리를 재생성하거나 회전 분리하지 않았다. 새 문지기에 적용한 기준은 다음과 같다.

1. 기준 이미지를 먼저 생성·검수·기록하고 모든 동작 생성에 같은 기준을 첨부한다.
2. 부위 조각을 관절에서 회전하는 대신 전체 자세 단위로 생성한다.
3. 크로마 배경을 알파로 정리한 뒤 분리된 찌꺼기와 끊어진 관절을 검사한다.
4. 프레임마다 외곽 크기에 맞춰 확대하지 않는다. 한 동작 시트에 하나의 축척만 적용해 웅크린 자세가 다시 커지는 오류를 막는다.
5. 발바닥은 최종 192×144 캔버스의 y=132에 맞추고, 게임 바닥 y=282에 접지한다. 넓게 뻗는 돌진 때문에 캔버스 폭을 늘려 기본 몸체가 줄어들지 않게 했다.
6. 모든 문지기 프레임은 공유 32색 팔레트와 0/255 알파를 사용한다. Point 필터·정수 화면 좌표·밉맵 없음·무압축을 적용한다.
7. 준비·공격·회수는 전투 상태에 맞는 프레임을 선택한다. 모든 그림을 같은 시간에 넘기는 방식으로 속도를 결정하지 않는다.

티크의 기존 픽셀 수작업 방식과 새 문지기의 이미지 생성 방식은 서로 다르다. 후자의 비율·자세 드리프트가 완전히 사라졌다고 단정하지 않는다. 공통 기준은 비율을 지키고, 잘못된 프레임을 선별하며, 게임 크기에서 다시 확인하는 과정이다.

## 이미지 제작과 수정

첫 문지기 제안은 둥근 황동 몸체와 시안 눈이 티크와 겹쳤다. 사용자 피드백 후 사용하지 않고 **IRON MAW**로 새 기준을 만들었다. 얼굴·눈·둥근 배 대신 각진 압착부와 네 다리, 남색 철판과 붉은 열 틈을 사용한다.

밝은 황금빛 공방과 검사실 컨셉은 각각 기존 구도를 참고 이미지로 첨부하여 야간 폐공장으로 다시 생성했다. 달빛, 어두운 남색 철판, 제한된 시안 전력과 작은 호박색 램프를 남겼다. 배경은 640×360·48색으로 변환했다. 생성 배경의 바닥 위치가 요청 좌표와 달라 최종 변환에서 상·하 구간을 분리해 실제 충돌선 y=282에 맞췄다.

소품은 한 컨셉 시트에서 바닥·벽·추·구슬·두 소켓·충전 기둥·톱니 충격파를 추출했다. 공통 40색 팔레트, 네이티브 크기 24–52px, 이진 알파로 내보냈다. 새 캐릭터나 소품을 코드로 그려 대체하지 않았다. 코드 사각형은 체력 막대, 공격 예고선과 UI에만 사용한다.

기본 이미지 크로마의 작은 RGB 편차는 알파 정규화로 제거했다. 동작 시트는 기준 이미지와 레이아웃 가이드를 함께 참조해 생성했다. 대기는 추가 생성으로 과한 상하 운동을 줄였으며, 마지막 프레임의 몸폭 축소는 최종 게임용 시퀀스에서 제외하고 첫 전체 자세로 복귀하게 했다. 제거한 소스 그림도 기록에 남아 있다.

## 코드와 첫 검증

- `CorePuzzle.cs`: 추/구슬의 서로 다른 이동, 목표 판정, 전 수 스냅샷 되돌리기, 방 초기화.
- `ReworkModel.cs`: 세 방 진행, 새 보스 상태, 피격·대시·코요테·버퍼, 체크포인트와 엔딩.
- `ReworkGame.cs`: 기존 티크 프레임과 새 에셋 표시, 입력, 한국어 UI, 실제 플레이어 캡처.
- `ReworkPilot.cs`: 해법과 일반 입력만 사용한 QA 진행. 무적·순간이동·체력 조작을 하지 않는다.
- `ReworkBuild.cs`: 별도 v2 씬과 WindowsV2 출력. v0.1 소스/씬 보존.

독립 탐색으로 만든 세 방의 해법을 실제 게임 C# 규칙에 재생했다. 전체 되돌리기가 초기 상태를 복원하는지, 다른 색 소켓이 오판정되지 않는지 검사했다. 문지기의 닫힌 장갑에 주먹이 통하지 않는지, 대시와 피격 보호, 체크포인트, 발판의 코요테 점프가 정확히 한 번의 더블점프를 남기는지도 검사했다.

첫 자동 진행은 엔딩에 도달했지만, 문지기가 이미 충전 기둥에 겹쳤을 때 즉시 장갑이 열리는 오류를 찾았다. 이전/현재 돌진 전면이 기둥을 실제로 통과해야 열리게 수정하고 회귀 검사를 추가했다. 실패한 개방 횟수에 따라 적 속도가 끝없이 증가하지 않도록 강화 단계를 남은 체력에서 계산한다.

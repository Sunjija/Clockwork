# 구현 기록 — 티크: 귀환 v0.1

작성: 2026-09-30 / 갱신: 같은 날 라이선스 활성화 후 Windows 빌드·720p 자동 실행 검증 완료. 아래 1~8절은 초기 구현 당시 기록이며 후속 결과는 9절에 기록했다.

## 1. 요청과 범위

사용자는 전자석 퍼즐 1페이즈와 문지기 액션 2페이즈 기획을 바탕으로 Unity 프로토타입 구현을 요청했다. 필요한 에셋은 직접 도트를 찍거나 이미지 생성으로 제작하도록 허용했다. 앞서 합의한 티크 기본 형태·걷기·뒤쪽 팔 공격과 코요테 타임을 유지했다. 원작 전체 제작, 추가 미니게임, 온라인 서비스는 범위에 넣지 않았다. 후속 요청에 따라 이번 프로토타입과 관련 문서·제작 도구를 커밋하고 GitHub에 푸시하는 것까지 전달 범위에 포함했다.

기존 `ClockworkPrototype`의 많은 개발 파일에 섞지 않도록 `unity/TiqueReturnPrototype`을 새 프로젝트로 구성했다. Unity 버전은 설치된 6000.5.3f1에 맞췄다. 새 프로젝트의 기본 PlayerSettings와 씬 기본 설정에는 같은 버전의 기존 프로젝트 텍스트 형식을 참고했고, 기존 씬 오브젝트와 URP 참조는 가져오지 않았다.

## 2. 캐릭터 보존과 소품 제작

`prototypes/tique-playground/Revisions/10/data.json`의 클립 경로와 프레임별 시간을 가져왔다. 원본 PNG 67장을 그대로 복사해 캐릭터 머리·몸통·관절 경계·발 접지선을 다시 훼손하지 않았다. 걷기는 이동 거리에 따라 프레임 시간을 진행시키고, 공중에서는 실제 수직 속도에 맞춰 포즈를 선택한다. 공격 판정은 0.12~0.22초에만 발생하도록 원래 타격 프레임 구간과 연결했다. 팔을 길게 만드는 대신 문지기의 약점을 지면 가까이 내려오게 설계했다.

새 소품은 도형 단위로 직접 픽셀을 배치했다. 철·황동·시안 표식·붉은 단자로 구성한 16색 팔레트, 불투명/투명만 있는 알파, 보간 없는 정수 좌표를 사용했다. 소품 11개, 배경 2개, 합성 효과음 8개를 준비했다. 현재 소품은 기능·실루엣 판별을 우선한 프로토타입 아트다.

제작 스크립트는 저장소의 `tools/art/build_return_assets.py`이며 에셋 해시는 `asset-provenance.json`에 있다. 외부 유료 사이트나 생성 크레딧을 사용하지 않았다.

## 3. 퍼즐과 이야기를 연결

문과 자석은 같은 전력 공급을 나눠 쓴다. 자석이 켜져 있을 때만 추를 붙잡고, 레일 이동이 끝난 뒤 전원을 끄면 압력판 위에 내려놓는다. 문에 전력이 공급되고 추가 놓여야 문이 열린다. 레일 이동 중 전원 변경을 막아 중간 위치에 추가 떨어지는 복구 불가능 상태를 피했다. 빈 자석만 옮긴 경우에는 원위치로 되돌려 복구할 수 있다. 문은 한 번 열린 뒤 기계적으로 고정된다.

시작의 폐기 분류 → 문지기의 식별 오류 → 과부하 해제 → 티크와 엘리아스 공방이라는 귀환처 확인 → 출구 통과로 짧은 이야기를 연결했다. 마지막 공격이 바로 엔딩으로 이어지지 않고, 단말 재검사를 직접 해야 이야기가 완료된다.

## 4. 조작과 문지기

120Hz 고정 간격으로 게임 모델을 갱신한다. Unity 화면은 최대 60fps이며 렌더링 위치만 픽셀에 맞춰 반올림한다. 1도트 막대도 반 픽셀에 걸리지 않도록 오브젝트의 중심이 아니라 좌상단을 정수화했다. PPU 64와 640×360 렌더 텍스처를 사용한다.

점프/더블점프, 120ms 코요테 타임, 100ms 점프 버퍼, 지상·공중 대시, 짧은 공격을 연결했다. 대시에는 무적을 부여하지 않았다. 착지 시 공중 행동을 회복하고, 한 공격이 여러 번 피격을 발생시키지 않도록 공격 번호를 추적한다. 타격 정지는 약 50ms다.

문지기는 휴식 → 추적 예고 → 내려치기 → 약점 노출 → 회수 → 충격파 예고 → 충격파 순으로 움직인다. 위치 추적은 예고 초반 0.4초 뒤 고정된다. 정비 자석 구역에 팔을 유도하면 노출 시간이 1.8초에서 2.8초로 늘어난다. 사망은 검사실 체크포인트로 복구한다. 두 번 사망 후 도움 선택 시 예고/반격 시간을 늘린다.

오프라인 배치 검토에서 문지기 몸체가 지면보다 12픽셀 높게 배치된 것을 확인해 y=92로 조정했다. 동일한 변경을 Unity 렌더링과 배치 검토 자료에 반영했다. 실제 엔진 화면 검증은 아직 아니다.

## 5. Unity 라이선스 제한과 검증 전환

실제 Unity 배치 빌드를 시도했으나 에디터가 프로젝트 임포트 전에 종료됐다.

```text
No valid Unity Editor license found. Please activate your license.
Exit code: 198
```

사용자가 지금 활성화하기 어렵다고 답했다. 인증 변경이나 추가 활성화 시도는 하지 않았다. 대신 게임 모델에서 Unity 의존성을 제거하고, Unity가 실제 사용하는 C# 파일을 그대로 .NET 검사 프로젝트에 연결했다. 별도 흉내 모델이나 JavaScript 포팅으로 검사 결과를 대체하지 않았다.

`ReturnPilot`은 이동·점프·대시·공격·상호작용 명령만 제출한다. 자동 플레이에서 위치 이동, 무적, 체력 변경, 퍼즐 강제 완료를 사용하지 않았다. 경계 조건 단위 검사는 필요한 초기 상태를 직접 구성한다. 이 둘의 검증 범위를 구분했다.

## 6. 완료한 검사

`QA/model-checks.json`: 14개 통과.

- 퍼즐 정상 순서, 문 개방 유지, 오조작 복구, 레일 이동 중 전원 조작 차단.
- 코요테 점프 후 더블점프, 유예 만료 후 추가 점프 제한, 착지 입력 버퍼 1회 소비.
- 대시로 발판 이탈, 공중 대시 반복 방지.
- 준비 구간 공격 무효, 타격 구간 한 번만 피해 적용.
- 피격 무적, 사망, 퍼즐 상태를 보존한 체크포인트.
- 자석 포획, 충격파 점프 회피와 지상 피격.
- 재검사·출구를 거쳐야 엔딩, 일시정지 상태 정지.
- 복합 입력 30초 동안 모든 애니메이션 프레임 인덱스 유효.
- 일반 입력만 사용한 전체 진행: 연습 단자, 대시, 충격파 점프, 자석 포획, 6회 타격, 재검사, 엔딩. 체력 4/4.

`QA/model-playthrough.json`: 상태 전환과 이벤트 기록. 정답을 아는 자동 입력의 시뮬레이션 시간은 약 48.3초다. 첫 플레이 체험 길이를 대신하지 않는다.

`QA/source-compile.json`: Unity 설치본의 실제 관리 DLL을 참조하여 런타임 어셈블리와 에디터 어셈블리를 Roslyn으로 각각 컴파일. 오류/경고 없이 통과. 검사용 참조 구성에서 모놀리식 DLL과 모듈 DLL이 중복되는 문제를 먼저 수정했다. 이 과정은 Unity 자체의 컴파일 파이프라인·임포터·빌드 실행이 아니다.

`QA/asset-checks.json`: 파일 해시, 67프레임 크기/알파/접지선, 소품 팔레트, 오디오 파일, 중복 없는 GUID와 씬 연결, 무압축 Point 임포트 설정 확인. 단독 씬과 메타 파일은 작성했으나 Unity 역직렬화 검증은 보류다.

## 7. 실제 엔진에서 남은 확인

1. 에디터 라이선스 확보 후 프로젝트를 열어 임포트와 저장된 씬 참조를 확인한다.
2. 한국어 글꼴, UI 잘림, 소리, 카메라와 픽셀 표시를 1280×720 및 1920×1080에서 확인한다.
3. Windows 빌드를 만든 뒤 `--return-smoke`로 실제 Unity 자동 진행 및 캡처를 얻는다. 일반 모델 검사와 같은 입력 드라이버다.
4. 사람의 키 입력으로 점프·대시·공격 전환, 실수 후 퍼즐 복구, 죽음·도움·재시도를 확인한다.
5. 처음 보는 사람의 이해 시간·클리어 시간·실패 위치를 기록해 약 5분 체험으로 조정한다. 필요하면 퍼즐의 단계 수와 문지기의 반격 기회를 조정하며 단순 대기 시간으로 분량을 늘리지 않는다.

`QA/layout-study.png`는 현재 에셋의 크기와 배치를 보는 오프라인 합성 이미지다. 이를 엔진 스크린샷이나 실행 확인 근거로 취급하지 않는다. 현재 전달물은 실행이 검증된 완성 배포본이 아닌 **검증 가능한 Unity 프로젝트 소스**다.

## 9. 라이선스 활성화 후 실제 실행 확인

사용자가 Unity Hub에 로그인했다고 알려준 뒤 다시 빌드했다. Unity가 Personal 라이선스를 정상 확인하고 프로젝트를 임포트했다. 에디터 내 모델·프레임 검사 13개가 통과했고 Windows 플레이어 빌드가 성공했다. 실행 파일은 `Builds/Windows/TiqueReturn.exe`다. 최초 임포트 시 Unity가 만든 기본 ProjectSettings와 패키지 잠금 파일도 저장했다.

처음 숨긴 창으로 자동 검사를 시도했을 때 화면 캡처가 null을 반환했다. 해당 검사 프로세스만 종료하고, 화면이 표시되는 게임 창에서 같은 빌드를 다시 검사했다. 일반 입력 드라이버를 이용한 퍼즐 → 공격 연습 → 문지기 전투 → 자석 포획 → 재검사 → 엔딩이 체력 4/4로 통과했다. 프로세스 종료 코드는 0, `runtime-result.json`의 `passed`는 true다. 숨긴 창의 캡처 실패는 플레이 기능 성공으로 취급하지 않는다.

`QA/Runtime720Visible/`에 실제 게임 캡처 7장, 이벤트 기록, 자동 검사 결과를 보관했다. 1280×720 시작 화면, 퍼즐 조작, 자석 포획, 엔딩을 이미지로 확인했고 한국어가 표시된다. 이후 자동화 옵션 없이 게임을 실행해 사용자가 직접 플레이할 수 있는 시작 화면을 열었다.

남은 확인은 사람의 실제 키 입력 감각, 음향 청취, 에디터 Play 모드, 1080p와 창 크기 변경 화면, 첫 플레이 기준 5분 분량이다. 기본 자동 진행 통과가 전시용 최종 품질 승인을 뜻하지는 않는다. 상단의 작은 목표 문구는 하단 여백이 좁아 후속 UI 조정 대상으로 기록한다.

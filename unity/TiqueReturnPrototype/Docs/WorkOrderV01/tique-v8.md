# 티크 V8 — 이미지 포즈에서 실제 재생까지

2026-09-30. **V8의 최종 모션은 사용자에게 거부됐다.** 사용자는 점프에서 손이 사라져 보이고 도트가 뭉치는 구간이 많다고 지적했다. 아래 제작·검사 기록은 실패한 반복의 보존 자료이며 시각 품질 승인이 아니다. 전신 이미지 트레이스로 진행한 [V9](tique-v9-tracing.md) 역시 최신 사용자 평가에서 점프를 포함한 전체 모션이 거부됐다.

작업 시작 때 사용자는 문지기 V7의 개선을 확인하고 같은 방식으로 티크 동작 개선을 요청했다. 당시 계획은 독립 정지 이미지 → 팔레트 고정 도트 변환 → 픽셀 프레임 편집 → 실제 게임 재생이었다. 실제 V8 프레임은 생성 전신 포즈를 충분히 따라 그리지 못하고 원본 부품과 새 연결선을 중심으로 구성돼 이 계획과 결과 사이에 차이가 있었다. 생성 영상이나 완성 애니메이션 시트를 사용한 것은 아니다.

## 먼저 확인한 문제

- 기존 대시의 실제 활성 프레임 03~06은 전부 같은 그림이었다.
- 점프·더블점프의 준비 프레임이 재생 코드에서 생략됐다.
- 이동 중에는 걷기 분기가 착지보다 먼저 선택되어 착지 흡수가 보이지 않았다.
- 대시 뒤 잔여 제동 자세가 다시 걷거나 착지하는 모습을 가렸다.
- 피격 시작부터 무적 점멸이 적용되어 짧은 피격 자세가 거의 보이지 않을 수 있었다.
- 퍼즐의 화면 이동은 smoothstep인데 발 위상은 선형 거리로 진행해 가속·감속 구간에서 발이 미끄러졌다.
- 공격의 허공 이펙트가 실제 명중 구간보다 먼저, 결과와 무관하게 표시됐다.

## 고정한 기준

원본 67개 티크 PNG 및 작업 지시의 원본 자산 309개를 보존한다. 새 폴더 `Resources/ReturnV2/TiqueV8`를 게임에 연결하며 원본은 비교 자료로 남긴다.

- 캔버스 64×64, 발 피벗 (32,56), 원본 대기 높이 48px.
- 원본의 불투명 13색, 이진 알파, Point·무압축·밉맵 없음.
- 큰 구형 머리, 좁은 몸통, 두 시안 눈, 하트, 짧은 관절과 작은 손 유지.
- 승인 걷기 14장은 그대로 보존한다. 머리 위치와 하트 아래 경계 수정을 되돌리지 않는다.
- 점프·대시·공격의 물리 값과 피해·입력·판정 시간을 변경하지 않는다.
- 대기는 편안한 기본 자세를 유지하며 발을 앞으로 내밀거나 전투 준비 자세로 바꾸지 않는다.

## 제작과 반복 검토

내장 imagegen으로 공격 준비, 뒤쪽팔 타격, 작은 웅크림, 공중 다리 모음, 대시 기울기를 각각 독립 이미지로 만든다. 기존 단일 이미지인 양손 밀기 세 방향과 피격 참고도 재사용한다. 변환된 이미지 자체와 소스 해시·크롭·팔레트 정보를 저장하고, 원본 머리·몸통·하트 픽셀을 보존하는 프레임을 직접 편집한다.

| 반복 | 실제 확인 | 결정 |
| --- | --- | --- |
| 공격 참고 1 | 팔이 가슴 안쪽에 접히고 아래를 향함 | 실제 타격 참고로 거절하고 원본 파일 보존 |
| 공격 참고 2 | 뒤쪽 어깨에서 가슴 앞을 교차해 작은 주먹이 몸통 오른쪽으로 나옴 | 포즈 참고로 채택. 머리·몸통을 통째로 교체하지 않음 |
| 도트 1 | 14클립 134프레임. 팔레트·알파·연결 검사 통과하나 팔이 얇은 직선, 밀기는 포크 모양, 공중 다리 모음이 약함 | 시각적으로 거절. 기술 검사 통과가 자연스러움의 증거가 아님 |

이후 팔·손 외곽과 준비·착지 노출을 정리하고 실제 Unity 렌더를 수집했지만, 사용자에게 V8 전체가 거부됐다. 짧은 팔을 직선으로 연결하거나 작은 손을 부분적으로 가져오는 방식은 연결·팔레트 검사 통과와 별개로 손 소실과 도트 뭉침 문제를 남겼다. V8 소스·PNG·QA를 삭제하지 않고 V9의 실패 비교 자료로 보존한다.

## 재생 수정

`TiqueAnimation`은 물리 모델과 분리된 표현 선택기다. 대시 → 공격 → 공중 → 착지 → 정지 중 대시 제동 → 걷기 → 대기 순서로 고른다. 초기 피격 자세를 먼저 보이고 이후 무적 점멸을 적용한다.

대시의 준비 포즈는 실제로 이동하는 첫 60ms에 표시하며 입력이나 이동을 지연하지 않는다. 기존 160ms 대시 시간 안에 모든 활성 포즈를 넣는다. 점프·더블점프 준비는 실제 상승과 동시에 보이고, 이후 수직 속도에 따라 상승·정점·낙하 자세를 유지한다. 착지는 기존 120ms 안에서 표시하며 이동 조작을 잠그지 않는다.

60Hz 화면 샘플을 실제 120Hz 모델 Tick으로 검사해 준비·활성·착지 프레임이 화면에서 생략되지 않는지 확인한다. 재생 이름만 늘려 프레임 수를 부풀리지 않는다.

## 검증 구분

- 자동 모델 검사: `Tools/Check-Source.ps1`, `QA/V8`의 프레임 선택 기록.
- 자동 자산 검사: `Tools/Review-TiqueV8.py`. 원본 보존, 팔레트·알파, C8 연결, 프레임 차이, 게임 PNG와 검토 PNG의 일치.
- 실제 렌더 검사: 명시적인 `--return-tique-review` 전용 실행. 생산 모델에 조작 명령을 보내고 Unity가 그린 전체 화면을 저장한다. 물리 키 입력 검증과 구분한다.
- 일반 게임 흐름: 기존 스모크로 퍼즐 → 문지기 → 전투 → 귀환을 확인한다.
- 사람의 최종 자연스러움·재미 승인은 자동 검사로 대체하지 않는다.

V8의 일부 전투 캡처에는 진입 보호 점멸이 섞여 있다. 몸 전체가 숨겨진 프레임은 손 모양만의 문제를 판단하는 독립 증거가 될 수 없다. 이를 분리하기 위해 V9의 렌더 검토 fixture에서만 최초 보호 점멸을 해제했다. 보호 점멸 교란이 있었다는 사실이 V8에 대한 사용자의 거부를 무효화하지는 않는다.

V9에서는 추가된 사용자 지시인 원본 머리31×27·몸통21×16·하트13×10, 모든 새 손의 손가락 없는4×4 둥근 공, 원본 Walk14/Idle8 보존을 고정하고 전신 트레이스 뒤 원본 픽셀 교정을 적용했다. 그 작업의37생성 이미지, 27선택 키, 실제 렌더·OS 키·미검증 범위와 V9 거부 상태는 [V9 기록](tique-v9-tracing.md)에 분리해 적었다.

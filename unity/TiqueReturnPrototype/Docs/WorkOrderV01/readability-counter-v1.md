2026-10-01, `3338c55` 기반 로컬 구현. 사용자 플레이 피드백 전 단계이며 GitHub에 push하지 않았다.

## 현재 상태: 식별성 방향 유지, 최종 에셋 제작 과정 보완

사용자는 모든 새 시각 에셋을 **이미지 생성 → 생성 원본 확인/공유 → 게임용 도트 에셋으로 파생 → 기존 애니메이션 제작 과정**으로 만들도록 명시했다. 이번 `ReadabilityArt`는 이미지 생성 없이 코드/네이티브 픽셀만으로 제작했으므로 요구된 제작 과정을 충족하지 못했다. 편집 원본이나 Piskel/APNG가 있다는 사실은 이미지 생성을 생략할 근거가 아니다.

다만 사용자는 후속 피드백으로 **현재가 훨씬 잘 구분된다**고 평가했다. 회색 연결벽·손잡이 황동 사각 추·청록 원형 구슬·사각/원형 홈이라는 식별성 방향은 유지한다. 현재 묶음은 **식별성 프로토타입 / 제작 과정 미준수 초안**이며, 최종 제작 완료라는 주장을 보류하는 것이지 전체 디자인이나 식별성 개선을 거절된 것으로 간주하는 것이 아니다.

해당 오브젝트의 실제 생성 원본에 기반한 이미지 우선 개선안을 만들되 현재 외곽·색·구분 방향을 보존한다. 사후에 무관한 무드보드를 생성해 현재 도형의 출처로 간주하는 방식은 허용하지 않는다. 지속 규칙은 저장소 루트 `AGENTS.md`에 기록했다.

파일과 작동 중인 프로토타입은 삭제하거나 변경하지 않고 보존한다. 낙하 반격 및 기존 퍼즐 규칙의 모델/빌드/런타임 검사 결과와 사용자 식별성 평가는 유지한다. 기술 검사만으로 최종 시각 에셋 제작 과정이나 최종 사용자 승인까지 통과했다고 판정하지 않는다.

## 현재 프로토타입의 플레이 변경

- 벽: 회색 연결 구조물. N/E/S/W 연결 마스크 16종으로 이웃 벽과 이어진다.
- 추: 황동색 사각 무게추와 큰 손잡이. 구슬과 다른 명확한 외곽.
- 구슬: 청록 원형, 굴러갈 때 회전 이음선. 지나간 칸에는 짧은 이동 잔상.
- 소켓: 바닥에 파인 사각/원형 홈. 올바른 물체가 도착하면 외곽 접점 점등. 잠금 모양 제거.
- 설명: 실제 물체 아이콘, 맞게 배치한 종류별 개수, 처음 미는 추/구슬의 짧은 안내.
- 규칙 유지: 추는 한 칸, 구슬은 장애물까지. 소켓이 구슬을 멈추지 않는다. 연결한 물체도 미완성 판에서 다시 움직일 수 있다. 원래 세 방과 저장된 해법 유지.

## 문지기의 새 반격 루트

낙하 위치 고정 → 표시 밖으로 실제 회피 → 문지기가 빈 바닥에 착지 → 장갑 노출 → 기존 X로 한 번 반격.

상태는 `Slam → CounterSettle(0.2s) → Open(0.2s 준비 + 1.6s 공격 가능) → Recover`다. 한 대 명중하면 바로 닫힌다. 준비 구간에서는 공격할 수 없으며 공격 가능한 순간에 기존 `stagger-open`의 마지막 노심 노출 프레임이 보인다. 준비만 0.2초로 압축했고 실제 캐릭터/보스 PNG는 변경하지 않았다.

회피 성공은 낙하의 기존 충돌 범위(중심에서 가로 68px, 발 높이 기준 바닥 위 75px)를 실제로 벗어났는지로 판단한다. 범위 안에서 대시 무적이나 피격 보호로 피해만 무시하면 반격 기회를 주지 않는다. 충분히 높게 점프해 피한 경우는 허용한다.

회피 착지 시 플레이어가 피한 방향으로 노심 방향을 고정한다. 노출 중 방향 변경이나 다음 공격은 없다. 잔여 충격파를 제거하고 마지막 체력 구간의 헛친 낙하에는 추가 착지 충격파를 만들지 않는다. 실제로 맞은 낙하는 기존 회복/충격파 규칙을 유지한다.

`CoreOpeningSource`로 기둥과 낙하를 구별한다. 기둥 충돌은 기존 일반 5.2초 / 도움 7초 / 최대 3대를 유지한다. 새 낙하 반격은 두 모드 모두 1.6초 / 최대 1대다. 노심의 실제 공격 위치에 픽셀 외곽 표시가 붙고 HUD가 기회 종류·남은 시간·타수 제한을 보여준다. 체력 9, 공격 피해 1, X/C/점프 조작은 유지했다.

## 제작 원본과 범위

현재 프로토타입 런타임은 `ReturnV2/ReadabilityArt`로 기존 추/구슬/소켓 이름을 덮어 읽는다. 기존 StateArt, 티크 TiqueV10, 문지기 WardenV7, 전투 배경 및 기둥 PNG는 보존한다. 코드/네이티브 픽셀로 31개 클립·77개 PNG를 내보냈다. 19색, 알파 0/255, Point, 밉맵 없음, 무압축. PNG/Piskel/APNG/픽셀 변경 목록과 재현 스크립트는 프로토타입 기록으로 보관한다. **식별성 방향은 사용자에게 긍정 평가를 받았지만, 이미지 생성 단계가 빠져 최종 제작용 에셋의 요구 과정을 충족하지 못했다.**

- 제작 스크립트: 저장소 루트 `tools/art/author_puzzle_readability.py`
- 편집 원본/검증: 저장소 루트 `art/return-readability-v1`
- Unity 리소스: `Assets/Resources/ReturnV2/ReadabilityArt`
- 순수 모델과 검사: `ReworkModel.cs`, `ReworkChecks.cs`
- 화면/설명: `ReworkGame.cs`, `ReworkUi.cs`, `WorldArtState.cs`
- 기존 동작 연결: `WardenAnimation.cs`

## 검증 범위

순수 C# 하네스는 기존 퍼즐 해법·Undo·종류 일치·연결 해제·소켓 통과·벽 마스크와 전투 17개 검사, 애니메이션 범위 검사 등을 수행한다. 실제 기둥 3타와 낙하 1타, 공격 불가 준비, 시간 만료, 헛주먹, 무적 악용 방지, 점프 회피, 마지막 구간의 충격파, 사망/재시작 초기화를 포함한다.

일반 입력만 보내는 자동 플레이 결과:

- 전체 여정 혼합 루트: 엔딩 / HP 5/5 / 기둥 1회·3타 + 낙하 6회·6타 / 106.40초.
- 기둥 없는 전투 루트: 일반 99.06초, 도움 108.82초 / 각각 HP 5/5 / 낙하 9회·9타. 시작 후 좌표·HP·보스 상태를 직접 변경하지 않는다.

이 시간은 해법을 알고 자동 입력한 결과다. 첫 플레이 시간이나 재미·난이도 검증값이 아니다. 자동 플레이 성공이 사용자 아트 승인을 대신하지 않는다.

### 실제 Unity GPU 캡처

별도 `--return-readability-review --return-offscreen-capture` 실행은 세 퍼즐 해법을 생산 코드의 이동 명령으로 재생하고, 명시한 초기 전투 배치에서 이동/대시/X 명령으로 낙하를 피하고 반격한다. 실제 월드 카메라 RenderTexture를 GPU 렌더링해 저장한다. 초기 전투는 통제된 QA 배치이며 전체 여정 플레이와 구분한다.

별도 `--return-v2-smoke --return-offscreen-capture`는 일반 입력 자동 드라이버로 타이틀부터 엔딩까지 진행한다. 기둥 충돌과 새 반격 캡처도 포함한다. 반격으로 처치가 가능하므로 예전 ‘기둥 3회 필수’ 검사는 ‘엔딩 + HP 0인 보스 + 기둥 루트 경험’으로 변경했다. 모델 자체는 기둥 횟수를 승리 조건으로 사용하지 않는다.

오프스크린 캡처는 IMGUI 글자·버튼, 운영체제 창, 물리 키 입력을 검수하지 않는다. HUD는 별도로 기존 글리프 포함 여부와 줄바꿈/패널 폭을 검사했다. 사용자 직접 플레이 검수는 별도다.

Mac 빌드 성공 후 반격 전용 GPU 캡처 13장과 전체 여정 런타임 검증이 모두 통과했다. 기록은 `QA/ReadabilityCounter/Runtime`와 `mixed-runtime-result.json`, `mixed-runtime-events.txt`에 저장했다. 일반 여정 런타임도 엔딩 / HP5/5 / 기둥1회 / 반격6회 / 106.40초다.

4. 반격 1.6초가 접근·공격하기 충분한가? 기둥 루트도 쓸 이유가 있는가?

시각 작업은 현재 벽·추·구슬·사각 소켓·원형 소켓의 잘 구분되는 외곽·색을 유지하는 개선 이미지를 실제로 생성하고 보여준다. 제로부터 재설계하거나 현재 프로토타입을 삭제하지 않는다. 생성 원본/프롬프트/참조/파생 매핑을 보존한 뒤 게임용 픽셀 크기와 기존 타이밍에 맞춰 파생한다. 개선 후보에서 사용자 피드백을 받은 후 타이밍을 조정한다. 보스 체력·새 무기·맵 재설계·캐릭터 재생성은 이번 범위에 포함하지 않는다.

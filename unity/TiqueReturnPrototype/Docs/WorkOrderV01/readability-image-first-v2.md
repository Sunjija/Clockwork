# 퍼즐 식별성 v2 — 생성 이미지 기반 네이티브 도트

2026-10-02. 기존 식별성 방향을 유지하는 **게임 연결용 외형 후보**다. 사용자 외형 승인과 재미 검증은 완료로 표시하지 않는다.

## 바뀐 범위

회색 연결 벽, 손잡이 달린 황동 추, 청록 구슬, 사각/원형 바닥 소켓과 낮은 대비의 바닥만 별도 `ReadabilityArtV2` 리소스로 교체한다. v1 파일은 동작하는 비교 프로토타입으로 보존한다. 티크 V10, 문지기 V7, 배경, 기존 HUD/VFX, 퍼즐 풀이·밀기·구슬 정지 규칙, 전투 반격·체크포인트·키 입력은 이번 외형 교체에서 바꾸지 않았다.

## 제작 순서와 출처

1. 10월 1일 내장 `image_gen`으로 실제 대상 6종의 기준 이미지를 생성했다. 두 소켓은 각 1회 이미지 편집했다. 총 8회 호출이며 77장의 독립 생성이라는 뜻이 아니다. 실제 이미지·프롬프트·참조와 실패 후보를 보존했다.
2. 생성 기준 이미지를 보여주고 검토한 뒤, 10월 2일 네이티브 도트를 파생했다. 거의 투명한 외곽 노이즈를 물체 경계로 쓰지 않도록 알파128 기준으로 크롭한다. premultiplied 면적 평균 축소, 약한 샤픈, 디더 없는 공유 팔레트, 제한적인 원본 기반 픽셀 정리를 사용한다. 사각 소켓의 얇은 황동 테두리는 실제 원본의 밝은 픽셀 면적을 반영해 보존한다.
3. 벽·바닥·소켓36×36, 추30×32, 구슬26×26로 등록한다. 추의 빈 손잡이·발, 구슬의 둥근 윤곽, 두 소켓의 어두운 빈 중심을 유지한다. 모든 네이티브 픽셀에 원본 영역과 변경 기록을 남긴다.
4. 티크/문지기에 사용한 네이티브 등록·편집 원본·PNG 출력 방식으로 31클립·77프레임을 내보냈다. 기존 클립명·크기·duration 배열과 배치를 유지한다. 정수 픽셀 편집은 원본에서 파생한 프레임의 이음선·손잡이·빛 반응에 한정한다. v1의 도형 페인터를 호출하지 않는다.
5. 출력 PNG는 이진 알파, 공유 최대48색, Point 필터, 밉맵·압축 없음, PPU64다. 각 클립의 Piskel, APNG(다중 프레임), 첫 프레임 대비 델타 및 네이티브 원본 대비 델타를 보존하고 재생 결과를 대조한다. 오배치 빨간 표시는 기존 처리의 변경 없는 재사용으로 출처를 별도 기록한다.

벽16종은 이웃 방향에 해당하는 테두리만 같은 생성 원본의 내부 픽셀로 연결한다. 추는 몸체·발을 고정하고 손잡이만1px 움직인다. 구슬은 외곽·고정 광원은 유지한 채 원본 내부 선의 픽셀을 이동한다. 소켓은 원본 테두리의 네 구역을 차례로 밝힌다.

## 게임 연결 및 검사

`ReworkGame`은 `ReturnV2/ReadabilityArtV2/`를 먼저 읽고, 없으면 보존된 v1을 읽는다. QA 실행에 `--require-readability-v2`를 넣으면 실제 v2 리소스를 읽었을 때만 통과한다. 원본·PNG 검사와 실제 Unity world-camera 캡처를 분리한다.

- [클립 출력 기록](../../../../art/return-readability-image-first-v2/Clips/export-manifest.json)

재생성 스크립트는 `tools/art/derive_readability_native_v2.py`, `tools/art/export_readability_v2.py`다. 독립 검사는 `tools/art/check_readability_v2.py --phase all`, 실제 캡처 패키징은 `tools/art/review_readability_runtime_v2.py`다. 원본 캐시 경로와 직접 비교하는 검사는 제작 PC의 추가 증거이며, 다른 PC에서는 저장소에 보존된 생성 PNG와 원본 SHA 기록을 사용해야 한다.

## 사용자와 확인할 부분

실제 화면에서 벽/추/구슬의 식별, 빈 소켓과 점등 소켓의 구분, 배경과의 조화, 밀기 접촉과 구슬 회전의 자연스러움을 확인한다. 특히 점등 상태는 물체 뒤의 얇은 테두리로 보이므로 눈에 충분히 들어오는지 플레이 피드백을 받는다. 자동 검사는 외형 승인이나 전투 재미를 대신하지 않는다.

# 「티크: 귀환 회로」 첫 작업 지시 v0.1 구현 기록

기준 커밋 7d83949. GitHub 번들 1,208줄 전체와 부록 A/B/C를 읽고 [구현 전 작업표](id-work-table.md)를 먼저 작성했다. [230 ID 연결표](id-implementation-index.md)는 실제 재사용/신규/생략 연결처를 기록한다. 캐릭터 비율, 67 티크 원본, 52 문지기 원본, 187 상태 프레임, 게임 규칙은 보존했다.

## 이미지부터 만드는 제작 과정

새 에셋의 흐름은 **동작·상태별 정지 이미지 → 고정 팔레트·네이티브 도트 변환 → 프레임별 픽셀 보정 → 게임 상태 연결**이다. 생성한 동영상이나 완성 애니메이션 시트를 자르지 않았다. 효과/UI 보드는 서로 다른 정지 부품이며 연속 동작 프레임이 아니다. 원본이 있는 동작은 그 원본 이미지를 우선 재사용한다.

1. 단일 밀기 이미지 3방향과 피격 이미지, 서로 다른 VFX/UI 정지 부품을 제작했다. 아래 밀기에서 큰 손가락·장갑이 나온 이미지는 거부하고 작은 닫힌 손으로 다시 제작했다.
2. 정지 부품 34개를 네이티브 격자·고정 팔레트·0/255 알파로 변환했다. 미세한 발광/배경은 제거했다. 한글은 사용자가 허용한 SIL OFL 픽셀 글꼴을 실제 글리프로 굽고, 생성 이미지로 글자를 만들지 않았다.
3. 티크의 머리/몸통/하트 기본형을 유지하고 팔의 가림 영역만 보정했다. 양손 밀기 14노출씩 3종은 승인된 Walk14의 머리와 발을 그대로 공유한다. 막힌 밀기 3종은 기본 Idle 발을 쓰므로 전진 발이 나타나지 않는다. 상하 이동에서 캐릭터 전체를 90도 회전하지 않는다.
4. 팔꿈치·손 접합부, 먼지 분산, 스파크 확장·소멸, UI 9분할 테두리를 픽셀로 수정했다. PNG/APNG/Piskel과 좌표별 픽셀 변경 JSON을 함께 보존했다. 완성본은 **53 공용 클립, 154 PNG 노출**이다. 이것은 230 ID의 개수와 다르다.
5. 시간 배열은 원본 티크를 유지했다. Walk760ms, Attack460ms, Dash440ms, Jump800ms, DoubleJump710ms. 새 효과는 명중170/피격170/장갑140/허공110/먼지200/공중추진170/브리지100/기둥150/낙하240ms. 효과의 종료 수명도 노출 시간에 맞췄다.

과정 원본: `art/return-v5-feedback/Source/Concepts`, 변환본: `Source/Native`, 애니메이션: `Clips`. `source-image-map.json`은 원본 SHA-256·크롭·네이티브 크기를, `clip-source-map.json`은 모든 완성 클립의 이미지 재사용 경로를 기록한다. `prompts-and-decisions.json`은 생성 목적·원본 참조·거부 근거를 보존한다.

## 좌표와 사건

| 대상 | 공통 기준 / 수정 |
|---|---|
| 티크 | 64×64, 발 (32,56). 원본 비율·머리·발 픽셀 유지 |
| 퍼즐·오프닝 발 | x=194+tileX×36+18, y=64+tileY×36+32. 자연 종료/스킵이 같은 칸·같은 발에 인계 |
| 추 | 30×32를 칸 x+3/y+0에 배치. 기존 +2px 아래 오차 제거 |
| 구슬 | 26×26을 x+5/y+6. 방출/정지 VFX는 실제 중심과 진행 방향의 ±13px 접촉면 |
| 퍼즐 이동 | 티크/추150ms, 구슬270ms 분리. 완성 판정 후에도 마지막 시각 이동이 끝남 |
| 밀기 | 양손 방향별 자세. 가로는 가까운 면에 두 손이 닿도록 손 크기 유지·접합 픽셀 보정. 상하의 2.5D 투영 자세는 캡처로 제시하고 최종 자연스러움은 사람 확인 대상 |
| 문지기 | 192×144, 발132. 노심 중심 WeakX/WeakY(bossY−20)를 판정/내부 반응/성공 스파크가 공유 |
| 기둥 연결 | 손→기둥 코일 두 좌표를 입력 순간 저장. 이후 이동하는 캐릭터를 따라가지 않음 |
| 지면 효과 | 마지막 먼지 픽셀이 공통 발/바닥선 위에 붙는 피벗. 공중 코요테 점프에서 지면 먼지를 만들지 않음 |
| UI | 640×360 격자. 패널 끝의 1·2px 조각은 UV도 같은 폭으로 잘라 정수 확대에서 반 도트가 생기지 않음 |

명중/장갑/허공/티크 피격은 별개 사건·효과다. 실제 접점에서 HP/소리/VFX/hitstop은 한 번만 발생한다. 취소된 공격의 판정은 남지 않는다. hitstop·정지·포커스 이탈은 월드/VFX의 같은 시간을 멈춘다. 되돌리기·초기화·전환·재도전은 이전 사건을 지운다. 전체 화면 플래시/거대한 폭발은 넣지 않았다.

## 인게임 연결

제목은 입력을 기다린다. Enter로 시작하면 같은 퍼즐 공간에서 14초 동안 통로→낙하→한 번의 착지→귀환 기록→회로0/3→조작 안내가 이어진다. 새 Enter로만 건너뛴다. 이동/공격 키로 건너뛰지 않는다. 인계에서 잔여 키·버퍼·누적 시간을 비우고 키를 떼야 다음 입력이 통과한다.

퍼즐 복구 완료800ms와 새 Enter → 문지기 전력 재가동2.4초 → 안전 안내의 새 Enter → 기존 전투 → 최종 타격의 위험/행동 정리 → 귀환문800ms → E 귀환이다. 재도전은 퍼즐·오프닝·부팅을 반복하지 않는다. 오프닝/조작/안내 시간을 별도로 기록한다. 자동 공략의 약68초를 첫 플레이 체험 시간이나 재미 검증으로 해석하지 않는다.

전투 키: 방향키 이동, **Z/Space/↑ 점프, X 공격, C 대시, E 상호작용**. 퍼즐은 방향키/Z 되돌리기/R 초기화/H 힌트. Esc 정지, F11 전체화면, M 소리. 코요테120ms와 입력 버퍼100ms는 원래 규칙을 유지한다. 같은 틱의 유효 행동 우선순위는 대시→점프→공격→상호작용.

UI는 하트 표식+5셀, 문지기9셀/3셀 구획, 피해50ms/소실 잔상200ms, 재도전200ms 채움, 보호·저체력·강화 표시, 키 캡/아이콘, 버튼4상태, 회로3칸, 정수 게이지다. 대시 준비 전용 표식은 문서에서 선택 사항이며 혼잡을 줄이기 위해 생략했다. 제목·귀환 문구는 실제 픽셀 글꼴과 기존 귀환문을 공유한다.

## 실행 및 검증 구분

현재 PC에서 Unity6000.5.3f1 Windows 빌드를 만들었다. 프로젝트의 `Play.cmd`는 `Builds/WindowsV5/TiqueReturn.exe`를 연다. 소스는 `Assets/Scripts/ReworkModel.cs`, `ReworkGame.cs`, `ReworkUi.cs`, `ReturnFeedback.cs`; 모든 새 그림은 Resources에 실제 연결되어 있다.

- 자동 모델/소스: `Tools/Check-Source.ps1`, 기존 검사와 작업 지시37검사. 입력 우선순위/스킵/같은 발 인계/한 번의 착지/접촉/취소/보호/정지/최종 타격/재도전을 검사한다.
- 자동 자산/렌더: `Tools/Review-WorkOrder.py`. 309 원본 SHA-256, 34 정지 이미지 변환, 53 클립 출처, 154 이진 알파 PNG, 밀기42프레임의 원본 머리·발/연결성, 381 글리프·OFL을 검사한다. Runtime720Accepted/Runtime1080/RuntimeNonInteger는 별도 Windows 프로세스에서 입력 전용 공략으로 종료까지 진행하고 실제 전체 화면을 캡처한다.
- 실제 키 입력: `QA/WorkOrderV01/Manual`에 Win32 창에 보낸 키·관측 결과·키마다 실제 게임 렌더 캡처20장을 별도로 기록한다. 전투 키 검사의 `--return-input-check`는 부팅이 끝난 안전 안내를 여는 **QA 시작점**이며 일반 `Play.cmd`에는 없다. 이 검사와 자동 공략을 사람이 직접 완주한 것처럼 합치지 않는다.
- 미검증: 사용자 최종 모션 품질 승인, 처음 보는 사람의 재미/난이도/소리 없는 판독, 다른 고DPI 모니터. 이 항목은 완료라고 표시하지 않는다.

빌드/검사 상세 결과는 `QA/WorkOrderV01`의 JSON·사건 기록·화면 캡처에 있다. 최종 handoff 기록은 별도 `verification-report.md`를 따른다.

# 상태별 에셋 도트화 — 2026-09-30

상태: `[proposal]` — 구현·검증 후 사용자 시각 검토 대상. 이 문서는 졸업작품용 독립 프로토타입의 기록이며 기존 본편 세계관·맵을 바꾸지 않는다.

## 누락과 수정 범위

v0.3에서는 문지기 동작을 픽셀 편집으로 다시 만들었지만, 충전 기둥과 소켓은 하나의 그림에 색을 곱해 상태를 표시했다. 보스 노심과 충격파에는 같은 가시 톱니를 사용했고 출구는 세로 막대였다. 사용자의 추가 지적에 따라 실제 상태를 보여 주는 스프라이트와 전환 프레임으로 교체했다.

이제 `ReworkGame`은 `ReturnV2/StateArt/clips.json`의 **37개 상태·전환 클립, 총 187 PNG 프레임**을 불러온다. 반복 노출과 정지 프레임을 포함한 수이며 187개의 서로 다른 디자인이라는 뜻은 아니다. 단순 진행률 막대와 HUD는 수치 UI로 유지한다. 상태가 없는 바닥·벽은 기존 도트를 사용한다. 티크 67프레임과 문지기 기존 52프레임은 보존한다.

## 이미지 먼저, 도트 편집은 그다음

`clockwork-art-director`와 `imagegen`의 컨셉·일관성·Unity 검수 기준을 적용했다. 사용자가 지정한 직접 픽셀 편집 방식을 우선한다.

1. 코드의 실제 상태를 먼저 조사했다. 퍼즐에서는 물체 종류·이동·소켓 점유, 전투에서는 충전·잔여 시간·충돌·노심 피격·전투 종료가 그림을 결정한다.
2. 기존 소품 컨셉에서 각 대상을 분리해 참고 이미지로 저장했다. 티크나 기존 소품의 기본 실루엣을 임의로 다시 생성하지 않았다.
3. 내장 이미지 생성 도구로 **단일 상태 참고 이미지 8장**을 만들고 확인했다: 충전 완료 기둥, 방전 기둥, 연결 소켓, 연결 추, 전용 노심, 닫힌 귀환문, 열린 귀환문, 전력이 돌아온 집행실.
4. 새 노심과 닫힌 문은 각각 한 번만 네이티브 해상도로 변환했다. 기존 소품은 기존 도트를 기준으로 썼다. 열린 문 참고 이미지를 별도로 잘라 중간 프레임으로 쓰지 않았다.
5. 도트 좌표로 회로, 잠금쇠, 축전 창, 전기 선, 노심 반응, 문짝 이동을 편집했다. 문틀·바닥 기준점·기본 부피를 고정했다. 모든 중간 프레임은 코드에 명시한 정수 픽셀 작업으로 만들었고 AI 애니메이션 시트는 사용하지 않았다.
6. 첫 상태 비교에서 비활성 소켓과 노심이 평평한 갈색 덩어리처럼 보였다. 단색 덮기를 제거하고 기존 명암을 유지하는 팔레트 변환으로 수정했다. 새 노심이 프레임 하단에 붙어 있던 문제도 수정해 기존 약점 위치에 맞췄다.
7. 문은 같은 문틀 안에서 두 문짝이 옆으로 수납된다. 내부 통로의 선과 명암만 직접 편집했다. 배경은 새 생성 이미지가 원래 건물 모양을 조금 바꿨으므로 조명 참고로만 사용하고, 실제 게임에서는 기존 네이티브 배경의 지정 조명·회로 픽셀만 바꿨다.
8. PNG·APNG·Piskel·시간 JSON·프레임별 픽셀 변경 목록을 저장하고 상태 선택 코드에 연결했다.

작업 방식은 **픽셀 좌표 편집과 원래 픽셀 덩어리의 정수 이동**이다. Piskel에서 마우스로 모든 프레임을 그렸다고 표현하지 않는다. Piskel 파일은 후속 편집용으로 제공한다.

## 티크 프레임 기준

- 추 이동: Tique `Dash`, 12프레임·440ms.
- 구슬·톱니 회전: Tique `Walk`, 14프레임, 시간 배열 그대로.
- 소켓 연결·기둥 전환·피격·예고: Tique `Attack`, 12프레임·460ms.
- 문 개방: Tique `Jump`, 15프레임·800ms.
- 정지 상태: 한 장 유지.

실제 물체 이동이 끝나면 움직임 클립은 해당 정지 상태로 전환한다. 예고와 충전 만료 같은 지속 상태는 정해진 프레임 시간을 반복한다. Piskel은 기존 티크 작업처럼 20FPS의 편집용 균등 미리보기이며, 가변 시간은 JSON/APNG와 Unity에서 확인한다. 동일한 연속 프레임은 APNG에서 합쳐질 수 있으나 총 노출 시간은 검사한다.

## 상태와 화면의 연결

`Assets/Scripts/WorldArtState.cs`는 실제 모델로부터 상태 이름과 시간을 계산한다.

- 소켓은 논리 좌표에 물체가 들어갔더라도 **화면상의 이동이 끝날 때까지** 빈 상태를 유지한다. 도착 후 연결 프레임을 재생한다.
- 되돌리기·초기화는 판의 현재 상태에서 그림을 다시 계산한다. 완료 불빛만 남아 있는 별도 상태 저장소를 두지 않는다.
- 한 칸만 움직이는 구슬도 실제 규칙의 270ms를 사용한다. 이전 화면은 거리만 보고 150ms로 추정해 움직임 시작이 지연되는 경우가 있었다.
- 기둥은 E 입력 시각과 실제 돌진 충돌 시각을 기록한다. 방전 460ms 이후 냉각 셔터를 표시하고, 2초 뒤 대기로 돌아간다. 충전 잔여 3초에는 만료 예고 그림을 반복한다. 자연 만료와 충돌 방전을 구분한다.
- 보스 피격 시각으로 노심 반응을 재생한다. 노심과 충격파는 이제 서로 다른 이미지다.
- 보스를 멈추면 문이 800ms 동안 열린다. 그 전에 E를 눌러 개방 모션을 건너뛰지 않도록 했다. 엔딩 전환으로 단계 시간이 초기화되어도 열린 문을 유지한다.
- 실제 캡처에서 보스 정지 후 냉각 안내가 남는 문제를 발견했다. 복구 단계에서도 기둥 타이머를 진행하고, 안내는 공격/충전 대신 전원 복구·귀환문 이동으로 전환했다.
- 마지막 소켓에 도착하는 그림이 보이도록 방 완료 오버레이와 다음 방 이동은 완료 후 800ms부터 허용한다.

## 해상도와 검수

640×360, PPU 64, Point 필터, 밉맵 없음, 무압축, 0/255 알파를 사용한다. 소품 팔레트는 검정 포함 47색이다. 꺼진 문지기는 기존 문지기의 32색 팔레트 안에서만 편집한다. 배경은 원래 48색에 조명 색을 더하되 64색 이하다.

기둥 발 기준선은 60px, 문은 96px이다. 문짝이 움직여도 문틀·문턱·알파 외곽은 같아야 한다. 배경 변경은 지정된 조명 위치 안에서만 허용한다. 전경 지형과 충돌 좌표는 바꾸지 않았다.

검사 파일:

- `QA/V4/state-model-checks.json`: 이동→접촉→접속→완료, 되돌리기, 틀린 소켓, 구슬 시간, 기둥 충전/만료/충돌/냉각, 노심, 문 상호작용 검사. 37개 시간표를 총 44,400회 샘플링한다.
- `QA/V4/state-art-checks.json`: 187 PNG의 픽셀 변경 재현, Unity 복사본 일치, Piskel 복원, APNG 총 시간, 팔레트·알파·임포트 설정, 문틀·배경 고정 검사.
- `QA/V4/Runtime720`, `Runtime1080`: 실제 실행 파일에서 일반 입력으로 퍼즐→보스→엔딩을 진행한 기록. `observed-art-states.txt`는 해당 실행에서 실제 렌더된 상태만 기록한다. 자연 만료와 틀린 소켓처럼 정답 자동 플레이에서 지나지 않는 상태는 모델 검사와 상태 도트 비교표로 구분해 검수한다.

자동 검사 통과는 사용자의 아트 승인을 대신하지 않는다. 모든 상태를 일반 플레이로 직접 봤다고 주장하지 않는다.

## 편집 파일과 재현

저장소 루트의 `art/return-v4-states`에 원본과 편집 자료를 보존한다.

- `Source/Concepts`: 상태별 생성 이미지 8장.
- `Source/prompts.json`, `Source/exit-open-prompt.txt`: 실제 생성 요청문. 내장 도구를 사용했다.
- `Source/Native`: 기존/신규 기준 도트.
- `Clips/<상태>/00.png`: 해당 상태·전환의 첫 프레임.
- `Clips/<상태>/<번호>.pixels.json`: **해당 클립의 00.png 대비** `[x,y,r,g,b,a]` 수정 목록.
- `Clips/<상태>/*.piskel`, `native.apng`, `sheet.png`: 애니메이션 편집·재생·시트.
- `manifest.json`, `pixel-edit-audit.json`: 상태 목록, 프레임 시간, 크기, 원본 역할, 픽셀 변경 수.
- `QA/state-contact.png`: 모든 소품 상태의 대표 프레임 비교표.

```powershell
# 저장소 루트에서 프레임 내보내기
python tools/art/author_return_prop_states.py

# Unity 프로젝트 폴더에서 검증·빌드
./Tools/Check-Source.ps1
./Tools/Build-Windows.ps1
python Tools/Review-State-Art.py
python Tools/Review-Authored.py
python Tools/Review-V2.py
```

실행은 `Play.cmd` 또는 `Builds/WindowsV4/TiqueReturn.exe`. 빌드 폴더는 Git에서 제외하며 소스·생성 원본·게임용 PNG·검증 기록을 저장한다.

## 최종 빌드 확인 · 2026-09-30

Unity 6000.5.3f1 Windows 빌드 성공. 최종 수정 후 1280×720, 1920×1080에서 각각 일반 입력 자동 플레이로 엔딩에 도달했다. 각 실행은 체력 2/5, 장갑 파괴 3회이며 25장씩 실제 화면을 남겼다. 자동 플레이의 53.46초는 정답 입력 경로의 시간이며 사람의 첫 플레이타임 추정값이 아니다.

각 해상도에서 37개 중 34개 상태가 실제 렌더된 것을 기록했다. 두 색상의 틀린 소켓과 충전 만료 예고는 이 정답 경로에서는 지나지 않으므로 모델 검사·상태 비교표 검수로 구분했다. 최종 화면에서 소켓 연결 테두리와 3단계 복구 조명, 기둥 방전, 열린 문과 보스 정지 후 안내를 확인했다. 두 실행 로그에서 예외/오류가 없고 `RETURN_V2_SMOKE PASS`를 확인했다.

빌드 결과·실행 파일 SHA-256은 `QA/V4/build-result.json`, 해상도·캡처 수·검수 범위는 `QA/V4/validation-summary.json`에 저장했다. 티크 67 PNG와 기존 프레임 시간, 문지기 52 프레임의 보존 검사도 통과했다.
